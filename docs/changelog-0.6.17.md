# 0.6.17 — внешний IP и имена артефактов для 1С

В версиях до 0.6.16 включительно `GET /api/v2/system/ip-check` возвращал только статус,
а публичная сериализация результатов убирала метаданные файлов. Версия 0.6.17 исправляет оба контракта.

Успешный ответ проверки IP:

```json
{ "status": "success", "ip": "203.0.113.10" }
```

`ip` — фактический адрес, полученный от ipify, после сравнения с настройками IP-монитора.
Ошибки чтения настроек, получения адреса, несовпадения и тайм-ауты сохраняют прежние HTTP-коды и формат.

Результат задания:

```json
{
  "artifacts": [
    {
      "filename": "validation.txt",
      "api_url": "/api/v2/jobs/JOB_ID/artifacts/ARTIFACT_ID"
    }
  ]
}
```

Такой формат возвращается в списке заданий, отдельном задании и callback.
1С берёт имя и расширение из `filename`, скачивает по `api_url` с заголовком `X-API-Key`.
Массив строк из версий 0.6.0–0.6.16 заменён массивом объектов: клиенты, ожидающие строки,
должны читать `item.api_url`. Веб-интерфейс обновлён и понимает оба варианта.

Внутренние пути файлов не публикуются. Уже сохранённые полные манифесты артефактов
получают имя при сериализации без повторного исполнения задания. Если старое состояние
содержит только URL и имени в нём нет, возвращается `filename: null`.

Версия 0.6.16 добавляла документацию и примеры JSON и не содержала этих исправлений.
Номер версии в ответе УН сам по себе не подтверждает наличие полей: после обновления
проверьте оба ответа API.
