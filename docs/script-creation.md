# Создание браузерных сценариев этапа 3

## Базовый принцип

Основной формат этапа 3 — JSON, экспортированный из **Chrome DevTools Recorder**. Сервис
не преобразует запись в собственный набор команд и не требует нового обработчика для
каждого сайта. Он проверяет запись официальной библиотекой `@puppeteer/replay`, ставит
задание в общую очередь и воспроизводит шаги в Chromium.

Один и тот же процесс используется для почты, личного кабинета, формы заявки или
произвольного другого сайта:

1. Аналитик записывает успешный проход в Chrome.
2. Экспортирует запись как JSON.
3. При необходимости заменяет изменяемые значения шаблонами `{{имя}}`.
4. Передаёт JSON и значения шаблонов в `POST /api/v2/jobs`.
5. Сервис валидирует и выполняет запись без изменения исходного кода приложения.

## Как записать новый сценарий

1. Откройте целевой сайт в Google Chrome.
2. Откройте DevTools (`F12`) и вкладку **Recorder / Запись**. Если вкладка скрыта,
   выберите меню DevTools → More tools → Recorder.
3. Нажмите **Create a new recording**, задайте понятное имя и начните запись.
4. Выполните весь бизнес-процесс до проверяемого конечного состояния.
5. Добавьте в Recorder проверки результата: наличие нужного элемента или текста.
6. Остановите запись и сначала воспроизведите её внутри Recorder.
7. Выберите **Export → JSON**. Не экспортируйте JavaScript: API принимает исходный
   Recorder JSON с полями `title` и `steps`.

Перед передачей записи рекомендуется:

- использовать устойчивые `id`, `aria` или `data-testid`-селекторы;
- удалить случайные клики и ввод, не влияющие на бизнес-результат;
- оставить явные `waitForElement` после входа, переходов и отправки форм;
- завершить сценарий проверкой результата, а не последним нажатием кнопки;
- не записывать CAPTCHA и ручное подтверждение второго фактора как автоматические шаги.

Для наглядности Фабрика поддерживает дополнительные метаданные каждого шага. Они не
меняют выполнение Puppeteer Replay, но отображаются в редакторе и ходе выполнения:

```json
{
  "title": "Указать получателя",
  "description": "Заполняет адрес получателя из context задания.",
  "type": "change",
  "selectors": [["#recipient"]],
  "value": "{{recipient_email}}"
}
```

## Параметры и секреты

Изменяемые строки в любом месте записи можно заменить шаблонами:

```json
{
  "type": "change",
  "selectors": [["#recipient"]],
  "value": "{{recipient_email}}"
}
```

Точные выражения сохраняют исходный JSON-тип, а выражения внутри текста подставляются
как строки. Значения передаются в `context` задания:

```json
{
  "uid": "mail-request-1c-000042",
  "timeout_ms": 45000,
  "context": {
    "recipient_email": "accounting@example.org",
    "subject": "Документы по заявке 42"
  },
  "script": {
    "title": "Отправка письма",
    "steps": [
      {
        "type": "navigate",
        "url": "https://mail.example.org"
      },
      {
        "type": "change",
        "selectors": [["#recipient"]],
        "value": "{{recipient_email}}"
      }
    ]
  }
}
```

`context` сохраняется в состоянии задания, поэтому пароли нельзя помещать в JSON
задания. Реальный Yahoo-сценарий использует серверные переменные `{{yahoo_mail_url}}`,
`{{yahoo_login}}` и `{{yahoo_password}}`, которые формируются из `.env`. Пароль
маскируется в параметрах шага и браузерных логах.

## Отправка в API

```bash
curl -X POST http://127.0.0.1:3000/api/v2/jobs \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: dev-secret' \
  -H 'Idempotency-Key: mail-request-1c-000042' \
  --data @job.json
```

Состояние и результат:

```bash
curl -H 'X-API-Key: dev-secret' \
  http://127.0.0.1:3000/api/v2/jobs/JOB_ID
```

Каждый шаг Recorder отображается в `execution.steps` со статусом, временем, параметрами
и текущим URL. Успешный запуск возвращает `runtime: "puppeteer-replay"`, `job_id`,
`uid`, `un_id` и финальный скриншот в `result.artifacts`.

## Поддерживаемые шаги Recorder

Исполнитель принимает стандартные шаги `setViewport`, `navigate`, `click`,
`doubleClick`, `change`, `hover`, `scroll`, `keyDown`, `keyUp`, `waitForElement`,
`waitForExpression`, `emulateNetworkConditions` и `close`. Поддерживаются альтернативные
CSS, ARIA, text, XPath и pierce-селекторы, а также обращения к iframe и вкладкам,
которые экспортирует Recorder.

`customStep` не является переносимым браузерным действием: для сценариев без участия
разработчика используйте стандартные шаги Recorder. Сайты с CAPTCHA, аппаратным ключом,
неавтоматизируемым MFA или запретом запуска Chromium требуют отдельного согласования.

## Проверка перед передачей

- JSON проходит проверку в редакторе на главной странице.
- Запись воспроизводится минимум два раза подряд на тестовом окружении.
- Последний шаг проверяет бизнес-результат (`waitForElement`), а не только клик.
- Селекторы не зависят от случайных CSS-классов или позиции элемента в списке.
- У задания уникальный `uid` или `Idempotency-Key`.
- Тайм-аут задания включает запуск Chromium, переходы и ожидания сайта.
- В логах нет непредусмотренных ошибок страницы.
- Итоговый скриншот показывает ожидаемое состояние.
