# API 0.14.0 — единая политика повторов и workflow-демонстрации

- Все принятые сценарии повторяются по retry_policy.max_attempts/backoff_ms, независимо от кода ошибки и формата. max_attempts включает первоначальную попытку.
- Удалены isRetryableError, принудительное retryable=false в JSON-исполнителе, флаги в InterpreterError и их передача через журналы/ответы исполнения worker. В job.error поле больше не выдаётся. Исторические ошибки нормализуются при восстановлении состояния.
- Тайм-аут шага допускает повтор. Отмена и истечение срока текущей попытки останавливают задание. После потери worker повтор ждёт нового готового подключения; при рестарте API учитывается уже использованная попытка.
- Артефакты следующих попыток сохраняются отдельно в attempt-2, attempt-3 и т. д. Входные параметры используются заново; внешние действия и перемещения XML не откатываются.
- В контексте workflow доступны attempt, artifact_dir и service_base_url. Поле job_id сохраняется.
- Исполняемые demo JSON, задания очереди/параллельности и примеры веб-редактора переведены на json-workflow. Удалены старые учебные цепочки, изображавшие ЭЦП/загрузку/проверку через специальные операции API. Браузерные записи выполняются через browser_steps; исходные записи вынесены в *.recorder.json.
- Файловые демонстрации загружают четыре формата с собственного учебного HTTP-сервиса, проверяют файлы, открывают сохранённый документ и возвращают снимок. Они не зависят от внешних сайтов с образцами файлов.
- Формат json-steps сохранён для совместимости существующих клиентских заданий; новые демонстрации его не используют.
- Поле retryable в /health и диагностике готовности worker сохранено: это подсказка для ожидания запуска сервиса, а не ограничение политики задания.

Инструкции: [повторы](operator-guide/13-retry-policy.md), [демонстрации](../demo/README.md).
