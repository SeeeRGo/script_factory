# Из Chrome Recorder JSON в сценарий универсальной системы

Инструкция соответствует исполнителю Script Factory 0.6.15 и формату `json-workflow`.
Она объясняет, что переносится из Recorder без изменений, а что нужно описать дополнительно.

## 1. Какие именно JSON сравниваются

Под «Puppeteer JSON» здесь понимается экспорт **Chrome DevTools Recorder → Export → JSON**, который воспроизводит библиотека `@puppeteer/replay`. Сам Puppeteer — библиотека управления браузером; произвольный JavaScript-скрипт Puppeteer не является записью Recorder и не переводится в наш формат простым переименованием полей.

Система принимает два варианта:

| Вариант | Когда использовать | Как исполняется |
| --- | --- | --- |
| Обычный Recorder JSON: `title`, `timeout`, `steps` с `type` | Один последовательный проход по сайту | Нативный исполнитель `puppeteer-replay` |
| JSON с `format: "json-workflow"` и шагами `action` | Параметры, ветвления, циклы, чтение данных, файлы, собственный результат | Универсальный исполнитель; браузерные записи внутри него запускает `@puppeteer/replay` |

Если достаточно последовательности кликов и ожиданий, запись можно отправить в API напрямую. Оборачивать её в workflow необязательно. Для полного сценария СБИС используется второй вариант.

Вся логика workflow хранится в JSON, но это не означает отсутствие программирования: поля `expression` содержат JavaScript-выражения. Новому сайту не нужен специальный обработчик в сервере, если достаточно уже имеющихся универсальных операций. Новая техническая возможность, которой в каталоге операций нет, потребует расширения исполнителя.

## 2. Что отличается

| Recorder / Puppeteer Replay | `json-workflow` | Правило переноса |
| --- | --- | --- |
| Корневой `steps` содержит `type` | Корневой `steps` содержит `action` | Вложить исходный массив в `browser_steps.params.steps` |
| `title` записи | `title` сценария | Скопировать |
| `timeout` записи | `browser_steps.params.timeout_ms` | Это тайм-аут Replay для браузерных шагов, а не всего задания |
| `navigate`, `click`, `change`, ожидания | Те же шаги внутри `browser_steps` | Сохранить `type`, `selectors`, координаты, `assertedEvents` и остальные поля |
| Браузер запускает исполнитель записи | Явный шаг `browser_launch` | Добавить до первой браузерной операции |
| Один линейный проход | `if`, `for_each`, `call`, `routines` | Выделить повторяемые блоки и описать управление процессом |
| Проверка DOM в `waitForExpression` | Также `browser_wait` и `browser_eval` | Оставить ожидание в записи либо вынести для работы с `context` и результатом |
| Нет нашего контекста результатов | `context`, `save_as`, `output` | Описать входные параметры, промежуточные значения и итог |
| Нет наших файловых операций | `files_list`, `file_verify`, `file_copy`, `file_archive` | Добавить отдельные универсальные шаги |
| Нет нашего блока обработки ошибки | `on_error` | При необходимости сформировать частичный результат |

**Не заменяйте `type: "click"` на `action: "click"`.** В workflow нет универсальной операции `click`: она является браузерным шагом внутри `browser_steps`. Аналогично `select_authority` не является допустимой универсальной операцией. Выбор ведомства описывается обычными шагами, условиями и проверками в JSON.

## 3. Подготовить исходную запись

1. В Chrome откройте DevTools → Recorder, создайте запись и выполните нужный проход.
2. Остановите запись, проверьте её воспроизведение в Recorder, экспортируйте **JSON**, а не JavaScript.
3. Уберите случайные действия и конкретные значения, которые должны стать параметрами.
4. После переходов добавьте ожидания готовности нужных элементов.
5. Завершите запись проверкой результата сайта. Успешный клик сам по себе не подтверждает завершение операции.
6. Проверьте селекторы и сохранённые события навигации на тестовом кабинете.

Предпочитайте стабильные `id`, `data-testid`, ARIA и понятные текстовые селекторы. Координаты `offsetX/offsetY` относятся к выбранному элементу; при изменении его размеров записанный клик может попадать в другое место.

Запись браузера не описывает произвольные окна Windows. Если сайт использует обычное `input[type=file]`, применяйте `uploadFiles`, описанный ниже. Для диалога стороннего приложения сначала нужно выяснить, доступен ли он в управляемом браузере. Нельзя считать, что Recorder автоматически управляет всеми нативными окнами.

## 4. Минимальный перенос: до и после

Исходная запись:

```json
{
  "title": "Открыть список документов",
  "timeout": 30000,
  "steps": [
    { "type": "navigate", "url": "https://example.org/documents" },
    {
      "type": "waitForElement",
      "selectors": [["#documents"]],
      "visible": true
    }
  ]
}
```

Workflow с той же последовательностью:

```json
{
  "format": "json-workflow",
  "title": "Открыть список документов",
  "default_step_timeout_ms": 60000,
  "context": {},
  "steps": [
    {
      "action": "browser_launch",
      "title": "Запустить браузер"
    },
    {
      "action": "browser_steps",
      "title": "Открыть документы",
      "description": "Выполняет исходную запись Recorder.",
      "params": {
        "timeout_ms": 30000,
        "steps": [
          { "type": "navigate", "url": "https://example.org/documents" },
          {
            "type": "waitForElement",
            "selectors": [["#documents"]],
            "visible": true
          }
        ]
      }
    }
  ],
  "output": { "state": "completed" }
}
```

Адрес и селекторы этого примера условные: их нужно заменить данными своего сайта.
Корневые поля записи, например `timeout`, не подхватываются автоматически из вложенного объекта. Исполнитель создаёт запись Replay из `params.steps` и `params.timeout_ms`.

Несколько блоков `browser_steps` работают в **одной браузерной сессии**. Запускайте `browser_launch` один раз. Между блоками можно читать DOM, считать значения и выполнять файловые операции; закрытие браузера после сценария выполняет исполнитель. Удалите записанный `close`, если дальше ещё нужны операции с этой страницей.

### Механически создать оболочку

В каталоге проекта сохраните экспорт как `recording.json`, затем выполните:

```bash
node --input-type=module <<'JS'
import { readFile, writeFile } from 'node:fs/promises';
import { parse } from '@puppeteer/replay';
const recording = JSON.parse(await readFile('recording.json', 'utf8'));
parse(recording);
const timeout = recording.timeout || 30000;
const script = {
  format: 'json-workflow',
  title: recording.title || 'Перенесённая запись',
  default_step_timeout_ms: timeout + 30000,
  context: {},
  steps: [
    { action: 'browser_launch', title: 'Запустить браузер' },
    {
      action: 'browser_steps', title: 'Выполнить запись Recorder',
      params: { timeout_ms: timeout, steps: recording.steps }
    }
  ],
  output: { state: 'completed' }
};
await writeFile('workflow.json', JSON.stringify(script, null, 2) + '\n', { flag: 'wx' });
JS
```

Это преобразует структуру и не перезаписывает существующий `workflow.json`. Команда не добавляет бизнес-проверки, циклы и выбор файлов. Тайм-аут оболочки нужно увеличить, если суммарное время браузерного блока больше заданного: Replay применяет свой тайм-аут к шагам, а оболочка ограничивает весь блок.

## 5. Вынести изменяемые значения в параметры

В исходном шаге замените конкретное значение шаблоном:

```json
{
  "type": "change",
  "selectors": [["#inn"]],
  "value": "{{inn}}"
}
```

Укажите значения по умолчанию в `script.context`, например:

```json
{ "inn": "0000000000", "submit_enabled": false, "departments": ["FNS", "SFR", "ROSSTAT"] }
```

При создании задания его `context` переопределяет `script.context`. Объединение поверхностное: переданный объект `ui` заменяет целиком одноимённый объект сценария, а не только отдельные вложенные поля.

| Запись | Значение |
| --- | --- |
| `"{{departments}}"` | Исходный массив, а не строка |
| `"{{submit_enabled}}"` | Boolean, если во входных параметрах передан Boolean |
| `"{{file.path}}"` | Поле вложенного объекта |
| `"Загрузить {{file.filename}}"` | Строка с подстановкой |

Шаблоны — это обращения к данным, а не язык вычислений. `{{inn == expected}}` не вычисляется. При отсутствии значения точная подстановка даёт `undefined`, а внутри строки — пустой текст; обязательные параметры проверяйте явно.

В JavaScript-выражениях используйте `context.inn`, а не вставляйте значение прямо в исходный код. ИНН храните строкой. Не путайте `false` с `"false"`: это разные типы.

`json-workflow` получает `script.context` и `context` задания. Он не наследует автоматически специальные серверные переменные Yahoo, которые добавляет прежний нативный исполнитель Recorder, и не предоставляет доступ к `.env` через выражения. `private: true` скрывает параметры и результат конкретного шага в событиях исполнения, но не удаляет исходный сценарий или `context` из сохранённого задания. Это не механизм хранения секретов.

## 6. Читать страницу и проверять значения

Внешние шаги в следующих примерах вставляются в `steps` workflow после запуска браузера.

```json
[
  {
    "action": "browser_wait",
    "params": {
      "expression": "document.querySelector('#organization-inn') !== null",
      "timeout_ms": 30000,
      "error_code": "ORGANIZATION_NOT_VISIBLE",
      "message": "Не найден ИНН организации"
    }
  },
  {
    "action": "browser_eval",
    "params": { "expression": "document.querySelector('#organization-inn').textContent.trim()" },
    "save_as": "actual_inn"
  },
  {
    "action": "compute",
    "params": { "expression": "context.actual_inn === context.inn" },
    "save_as": "organization_verified"
  },
  {
    "action": "assert",
    "params": {
      "condition": "{{organization_verified}}",
      "error_code": "WRONG_ORGANIZATION",
      "message": "Открыта другая организация"
    }
  }
]
```

`save_as` сохраняет результат в переменную верхнего уровня `context`. Используйте имена вида `actual_inn`; `save_as: "result.inn"` недопустим.

| Операция | Где вычисляется | Доступ |
| --- | --- | --- |
| `compute` | Изолированный worker/VM | Копия `context`, обычные вычисления; нет DOM, Node, файлов и `.env`; только синхронное выражение, лимит 1 секунда |
| `browser_eval` | Текущая страница | DOM и копия `context`; допускается Promise; результат можно сохранить |
| `browser_wait` | Текущая страница | Повторяет проверку до истинного результата; возвращает полученное значение |
| Recorder `waitForExpression` | Внутри Replay | Ожидание из записи; не рассчитывайте на переменную `context`, добавляемую нашими браузерными операциями |

`expression` должен быть выражением. Для нескольких инструкций используйте функцию с немедленным вызовом: `(() => { const value = ...; return value; })()`. Возвращайте JSON-совместимые значения, а не DOM-элементы или функции. Изменение копии `context` внутри выражения не обновляет контекст исполнителя: сохранение результата выполняет `save_as`.

## 7. Условия и запрет отправки

`if` и `assert` принимают **Boolean**, а не строку с кодом. Сначала вычислите условие, затем передайте результат.

```json
{
  "action": "if",
  "params": { "condition": "{{submit_enabled}}" },
  "then": [
    {
      "action": "browser_steps",
      "title": "Отправить документ",
      "params": {
        "steps": [
          { "type": "click", "selectors": [["#send"]], "offsetX": 10, "offsetY": 10 }
        ]
      }
    },
    {
      "action": "browser_wait",
      "params": { "expression": "document.querySelector('#status')?.textContent.trim() === 'Отправлено'" }
    }
  ],
  "else": [
    { "action": "set", "params": { "state": "prepared_without_submission" } }
  ]
}
```

Пример предполагает, что организация, документ и результат проверки подтверждены предыдущими шагами. Для рабочего процесса добавьте эти проверки перед нажатием. Если отправка началась, но подтверждение не получено, результат нужно сверять с сайтом до нового запуска.

## 8. Циклы и подпрограммы

В корневой объект добавьте `routines`:

```json
{
  "open_department": [
    {
      "action": "browser_steps",
      "params": {
        "steps": [
          { "type": "navigate", "url": "{{department.url}}" },
          { "type": "waitForElement", "selectors": [["#reports"]], "visible": true }
        ]
      }
    }
  ]
}
```

А в `steps` добавьте цикл:

```json
{
  "action": "for_each",
  "params": { "items": "{{departments}}" },
  "as": "department",
  "index_as": "department_index",
  "steps": [
    { "action": "call", "routine": "open_department" }
  ]
}
```

В этом примере `departments` — массив объектов с `url`, например `[{"url":"https://example.org/tax"},{"url":"https://example.org/statistics"}]`. Он отличается от массива строк в примере параметров: выбирайте структуру по потребностям сценария.

Итерации выполняются последовательно. Переменная элемента и индекса временные; после цикла прежние значения восстанавливаются. Параметры `call.params` также временные. Остальные значения, записанные через `set` или `save_as`, сохраняются.

Подпрограмма — массив шагов внутри JSON, а не функция сервера. Разбивайте сценарий по смыслу: вход, выбор организации, открытие раздела, загрузка, проверка результата. Для накопления результатов вычисляйте новый массив через `compute` и сохраняйте его через `save_as`.

## 9. Файлы на УН и загрузка в браузер

Чтение списка и выбор XML по префиксу:

```json
[
  {
    "action": "files_list",
    "params": { "directory": "{{root_dir}}" },
    "save_as": "available_files"
  },
  {
    "action": "compute",
    "params": {
      "expression": "context.available_files.filter(f => f.filename.toLowerCase().endsWith('.xml') && f.filename.startsWith(context.prefix)).sort((a,b) => b.modified_ms-a.modified_ms || a.filename.localeCompare(b.filename))"
    },
    "save_as": "selected_files"
  },
  {
    "action": "compute",
    "params": { "expression": "context.selected_files.length > 0" },
    "save_as": "files_found"
  },
  {
    "action": "assert",
    "params": { "condition": "{{files_found}}", "error_code": "NO_FILES", "message": "Подходящие XML не найдены" }
  }
]
```

`files_list` перечисляет обычные файлы непосредственно в каталоге, без рекурсивного обхода. Каждый объект содержит `path`, `filename`, `size_bytes`, `modified_ms`, `sha256`. Правило фильтрации находится в JSON. Здесь выбраны все совпадения, отсортированные по времени; если нужен только последний, добавьте `.slice(0,1)`.

В цикле `for_each` с `as: "file"` можно использовать:

```json
[
  { "action": "file_verify", "params": { "file": "{{file}}" } },
  {
    "action": "compute",
    "params": { "expression": "[context.file.path]" },
    "save_as": "upload_paths"
  },
  {
    "action": "browser_steps",
    "params": {
      "steps": [
        {
          "type": "customStep",
          "name": "uploadFiles",
          "parameters": { "selector": "input[type=file]", "files": "{{upload_paths}}" }
        }
      ]
    }
  }
]
```

`uploadFiles` — наше расширение, а не стандартная запись клика по диалогу. Форма загрузки должна быть уже открыта. Шаг передаёт файл в `input[type=file]`, после чего сайт может сразу начать импорт. Затем обязательно проверьте результат импорта на сайте. Для нескольких файлов поле должно поддерживать `multiple`. Другие имена `customStep` не поддерживаются.

Пути относятся к файловой системе **УН, исполняющей задание**, а не компьютера 1С. В JSON Windows-путь записывается как `"C:\\Reports\\incoming"` либо `"C:/Reports/incoming"`. Все файловые операции ограничены `FILESYSTEM_ALLOWED_ROOTS`, включая проверку реальных путей. Целевые каталоги для копирования и архивирования должны уже существовать.

После подтверждённого результата можно добавить:

```json
{ "action": "file_archive", "params": { "file": "{{file}}", "directory": "{{loaded_dir}}" } }
```

Архивирование проверяет SHA-256, копирует без перезаписи существующего файла, сверяет контрольные суммы и удаляет источник. Сам исполнитель не знает, когда документ считается обработанным: условие разрешения архивирования задаётся предыдущими проверками и ветками JSON.

## 10. Ожидания и тайм-ауты

| Поле / операция | Что ограничивает |
| --- | --- |
| API `timeout_ms` | Всё задание, включая запуск браузера и все итерации |
| `default_step_timeout_ms` | Обычный внешний шаг workflow; по умолчанию 60000 мс |
| Внешний `step.timeout_ms` | Весь конкретный шаг; для `browser_steps` — весь блок |
| `browser_steps.params.timeout_ms` | Тайм-аут шагов Replay; по умолчанию 30000 мс |
| `browser_wait.params.timeout_ms` | Ожидание конкретного DOM-условия |
| `wait.params.duration_ms` | Фиксированная пауза |

У `if`, `for_each` и `call` нет отдельного тайм-аута по умолчанию: действуют тайм-аут задания и ограничения вложенных операций. При необходимости укажите блоку собственный `timeout_ms`.

Для длинного ожидания увеличьте оба ограничения, например `browser_wait.params.timeout_ms: 120000` и внешний `timeout_ms: 125000`. Одно увеличение внутреннего тайм-аута не отменяет более короткий внешний.

Для простой паузы используйте:

```json
{ "action": "wait", "params": { "duration_ms": 2000 } }
```

`waitForExpression` с Promise и `setTimeout` технически тоже может задержать проход, но это не проверка готовности сайта. После загрузки лучше ждать конкретный элемент, текст или статус.

## 11. Результат, артефакты и ошибки

Для явного результата добавьте шаг и корневой `output`:

```json
{
  "action": "compute",
  "params": { "expression": "({state:'completed',organization_verified:context.organization_verified})" },
  "save_as": "answer"
}
```

```json
{ "Rezult_1": "{{answer}}" }
```

В ответе `GET /api/v2/jobs/{job_id}` это будет `result.context.Rezult_1`. Имя `Rezult_1` — договорённость сценария, а не обязательное поле движка. Если `output` не указан, исполнитель возвращает весь контекст, поэтому лучше задавать проекцию явно.

Чтобы сохранить текст или снимок:

```json
[
  { "action": "artifact_write", "params": { "filename": "validation.txt", "text": "{{validation_text}}" } },
  { "action": "browser_screenshot", "params": { "filename": "final.png" } }
]
```

Артефакты автоматически попадают в результат. Имена должны быть уникальными в задании, без путей; запись поверх существующего файла запрещена. В цикле используйте имя с индексом, например `"validation-{{department_index}}.txt"`. Workflow не делает финальный снимок автоматически при успехе: добавьте его явно. При доступном браузере исполнитель пытается сохранить диагностический снимок при ошибке.

При необходимости добавьте корневой `on_error`:

```json
[
  {
    "action": "compute",
    "params": { "expression": "({state:'failed',code:context.error.code})" },
    "save_as": "answer"
  }
]
```

Этот блок не превращает ошибку в успех. Он формирует частичный результат; исходная ошибка сохраняется. При отмене задания блок не запускается. Не помещайте туда отправку или архивирование. Возврат частичного результата через API при тайм-ауте или отмене отличается от обычной ошибки: не рассчитывайте, что он всегда будет доступен.

Автоматический повтор всего workflow после ошибки исполнения отключён (`retryable: false`). Повторный запуск выполняется явно после проверки состояния сайта.

## 12. Отправить из 1С или другого клиента

Можно передавать сценарий объектом в `script` либо целиком сериализованным JSON в `script_text`. Одновременно оба поля передавать нельзя.

Формат с отдельными параметрами:

```json
{
  "parameters": {
    "uid": "recorder-demo-0001",
    "timeout_ms": 180000,
    "context": { "inn": "0000000000", "submit_enabled": false }
  },
  "script_text": "{\"format\":\"json-workflow\",\"steps\":[{\"action\":\"wait\",\"params\":{\"duration_ms\":100}}],\"output\":{\"state\":\"completed\"}}"
}
```

В 1С прочитайте файл сценария как UTF-8 строку, присвойте её полю `script_text`, затем сериализуйте **весь объект запроса** штатным JSON-сериализатором. Не экранируйте кавычки вручную и не сериализуйте строку сценария ещё раз до присвоения. Не смешивайте `parameters` с одноимёнными параметрами задания верхнего уровня.

Для примера из репозитория создать запрос можно так:

```bash
node --input-type=module <<'JS'
import { readFile, writeFile } from 'node:fs/promises';
const script_text = await readFile('demo/recorder-conversion-workflow.json', 'utf8');
const request = {
  parameters: { uid: 'recorder-demo-0001', timeout_ms: 60000, context: {} },
  script_text
};
await writeFile('job.json', JSON.stringify(request, null, 2) + '\n');
JS

curl -X POST http://127.0.0.1:33001/api/v2/jobs \
  -H 'Content-Type: application/json' \
  -H "X-API-Key: $SF_API_KEY" \
  --data-binary @job.json
```

Адрес и порт замените на адрес своей УН; `SF_API_KEY` — переменная клиента с настроенным API-ключом. После POST возьмите возвращённый `job_id` и проверяйте:

```bash
curl -H "X-API-Key: $SF_API_KEY" \
  http://127.0.0.1:33001/api/v2/jobs/JOB_ID

curl -H "X-API-Key: $SF_API_KEY" \
  http://127.0.0.1:33001/api/v2/jobs/JOB_ID/logs
```

Для другого намеренного запуска используйте новый `uid`. Повтор того же идентификатора с другим содержимым запроса приводит к конфликту. POST ставит задание в очередь; успешный ответ POST ещё не означает успешное исполнение.

## 13. Как проверить перенесённый сценарий

1. Проверьте JSON-синтаксис и структуру workflow.
2. Выполните только вход и переходы на тестовом окружении, затем добавляйте чтение DOM и условия.
3. Проверьте правильные и неправильные параметры: другая организация, отсутствие файла, неоднозначный элемент, запрет отправки.
4. Убедитесь, что финальное состояние проверяется по данным сайта.
5. Проверьте результат и фактически выполненные шаги через API.
6. Только после этого включайте операции с внешними последствиями.

Локальная проверка структуры в каталоге проекта:

```bash
node --input-type=module <<'JS'
import { readFile } from 'node:fs/promises';
import { validateWorkflow } from './src/workflow-schema.js';
import { parse } from '@puppeteer/replay';
const script = JSON.parse(await readFile('demo/recorder-conversion-workflow.json', 'utf8'));
const errors = validateWorkflow(script);
if (errors.length) throw new Error(JSON.stringify(errors, null, 2));
for (const step of script.steps) {
  if (step.action === 'browser_steps') {
    parse({ title: script.title, timeout: step.params.timeout_ms || 30000, steps: step.params.steps });
  }
}
console.log('Структура workflow и непосредственных браузерных блоков корректна');
JS
```

Эта команда проверяет браузерные блоки непосредственно в `script.steps`. Блоки в подпрограммах, ветках и циклах нужно обходить отдельно; шаблоны, задающие типизированные значения, проверяйте после подстановки тестового контекста. Валидация структуры не доказывает, что селектор подходит реальному сайту. Внутренние браузерные записи также проверяются Replay при исполнении соответствующего блока.

История workflow раскрывается динамически: отдельные внешние операции, вызовы и итерации добавляются по мере выполнения. Один `browser_steps` — одна внешняя операция в истории, а не отдельная запись на каждый вложенный клик. Для подробной диагностики разбейте запись на несколько именованных блоков. `total_steps` может расти во время исполнения.

Лимиты текущего исполнителя: до 1000 элементов в одном цикле, 10000 исполненных внешних шагов и 25 уровней вложенности. Одна основная управляемая страница используется для `browser_eval` и `browser_wait`; наличие у Replay полей `target`/`frame` не означает, что эти две операции автоматически читают другую вкладку или iframe.

## 14. Частые ошибки при переносе

| Ошибка | Как исправить |
| --- | --- |
| Корневой `steps` содержит смесь `type` и `action` | Оставить сверху только универсальные операции; `type` вложить в `browser_steps` |
| Не добавлен `browser_launch` | Запустить браузер до браузерных операций |
| Каждая подпрограмма запускает новый браузер | Вынести запуск перед циклом; повторный запуск отклоняется |
| `if.condition` содержит `"context.ok"` | Вычислить Boolean через `compute`, передать `"{{ok}}"` |
| Ожидание на 120 секунд обрывается через 60 | Увеличить внешний тайм-аут шага и общий тайм-аут задания |
| Отправка считается успешной сразу после клика | Добавить проверку статуса и идентичности документа |
| Вместо массива файлов получена строка | Использовать точную типизированную подстановку и массив во входных данных |
| Передан путь с компьютера 1С | Разместить файл на исполняющей УН в разрешённом каталоге |
| Нужен специальный шаг `select_authority` | Описать переход и подтверждение ведомства стандартными браузерными операциями |
| Результат содержит все внутренние данные | Задать `output`; ограничить подробные события через `private` нужных шагов |
| Нативная запись использует Yahoo-шаблоны из `.env` | Учесть, что workflow не получает эти серверные переменные автоматически |
