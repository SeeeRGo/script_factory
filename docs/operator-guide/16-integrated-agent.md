# Установка и обновление API вместе с агентом (0.17.0+)

Общий установщик теперь включает агент. Версии API и исходников агента показаны в панели отдельно. Для установки агента впервые по-прежнему нужна индивидуальная регистрация в центре: ключ не создаётся из воздуха и административный токен центра не переносится на УН.

## Новая УН

Подготовьте индивидуальный JSON командой регистрации из [инструкции 15](15-agent-bootstrap.md) и публичный ключ, которым подписываются релизы. Передайте их **тому же установщику**, которым ставите API:

```powershell
# Выполнять на целевой УН из PowerShell администратора.
C:\script_factory\windows\install-task.ps1 `
  -ProjectPath C:\script_factory `
  -EnvFile C:\script_factory\.env `
  -Port 33001 `
  -FleetConfigFile C:\Deploy\enrollments\un-nefedov-test.json `
  -ReleasePublicKey C:\ScriptFactorySigning\release-public.pem
```

Это пример для указанной УН: выберите её индивидуальный JSON и фактические пути. Если используете `windows/deploy-one-un.ps1`, передайте ему такие же `-FleetConfigFile` и `-ReleasePublicKey` дополнительно к обычным параметрам архива/версии/контрольной суммы. `install-fleet-bootstrap.ps1` с `-EnrollmentDirectory` и `-ReleasePublicKey` тоже передаёт их общему установщику автоматически.

После установки API независимая задача SYSTEM ставит агент и проверяет его контакт с центром. При необходимости сначала войдите под robot, чтобы worker стал готов. Установка задачи API и завершение обновления агента — разные этапы: окончательное подтверждение смотрите в панели и `agent-sync-result.json`.

Без регистрации и этих файлов API можно установить автономно. Установщик явно сообщает, что агент не настроен; такая УН не становится управляемой автоматически.

## Последующие обновления

Установленные ключ, node_id, UN_ID, central_url, пути и индивидуальный каталог данных сохраняются. Повторно передавать JSON или административный токен не нужно. Отличающийся JSON блокируется: для восстановления/перевыпуска ключа используйте явный `-RecoverExisting` из инструкции 15.

- После проверенного обновления API помощник планирует обновление агента из нового релиза.
- Запуск нового API под SYSTEM также проверяет агента. Это позволяет перейти со старого updater, который ещё не вызывал новый помощник.
- Новая независимая задача Windows ожидает завершения операции, подтверждения накопленных результатов центром и готовности API вне обслуживания. По умолчанию ожидание — до 10 минут.
- Затем задача останавливает только агент, повторно проверяет журнал, сохраняет его код/конфигурацию/задачу, устанавливает новую копию и ждёт подтверждённого контакта до 2 минут.
- Если установка или контакт не подтверждены, прежний код, настройки и задача восстанавливаются. Сам API этим откатом агента не откатывается. Его обновление/откат ведётся отдельным штатным помощником.

Агент не заменяет свои файлы из собственного процесса: задачу запускает планировщик Windows, она находится вне дерева процессов агента. Понижение версии и обновление намеренно отключённой задачи блокируются.

При старой ошибке, которая останавливает обновление **до запуска нового API**, новый код ещё не может выполниться. Для такой УН один раз обновите/восстановите агент массовой командой из инструкции 15, затем повторите обновление API. Существующее неподтверждённое обслуживание автоматически не снимается.

## Проверка и журналы

В колонке версий панели теперь отдельно видны `API` и `Агент`; для старого агента без этих сведений будет «неизвестна». «Ожидается обновление» означает, что задача ещё не завершена. Успешный API-релиз не заменяет подтверждение версии агента.

На УН по умолчанию:

- `C:\ProgramData\ScriptFactoryAgent\agent-source.json` — установленная версия исходников;
- `C:\ProgramData\ScriptFactoryAgent\agent-sync-result.json` — `pending`, `succeeded` или `failed`, целевая версия и время;
- `C:\ProgramData\ScriptFactoryAgent\agent-sync.log` — подробный протокол замены;
- `<data_dir>\agent-contact.json` — версия/время последнего подтверждённого контакта;
- `<data_dir>\agent-err.log` — ошибки процесса.

В планировщике временная задача называется `ScriptFactory-AgentSync-*`, постоянная — `ScriptFactory-Fleet-Agent`. При успехе временная задача и её защищённый комплект удаляются. При ошибке защищённый комплект `C:\ProgramData\ScriptFactoryAgentSync-*` сохраняется для диагностики; при первой установке журнал до создания каталога агента может находиться в `C:\ProgramData\ScriptFactoryAgentFirstSync-*`. Не публикуйте эти каталоги: при первой установке в них есть индивидуальная регистрация.

Для нестандартного каталога агента помощник поддерживает `-InstallDir` и `-TaskName`; автоматические вызовы общего установщика используют стандартную установку. Параметры ожидания доступны в `windows/sync-installed-fleet-agent.ps1`: `-WaitSeconds`, `-ContactSeconds`. После исправления причины можно повторить помощник из актуального полного проекта с `-Defer`, `-ProjectPath` и `-EnvFile`; активная операция не будет прервана.
