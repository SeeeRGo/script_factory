# Установить и запустить агенты с главной УН

Требуется комплект проекта **0.15.2+** на главной УН. Первоначальную установку независимого агента теперь выполняет `windows/deploy-fleet-agents.ps1`. Список целей — существующий `C:\Deploy\nodes.csv` с колонками Computer,EnvFile; значения UN_ID/PORT берутся из подготовленных локальных env. API на целевых УН уже должен быть установлен. Скрипт не устанавливает Node, API или СБИС и не меняет учётную запись worker, настройки входа Windows и AutoAdminLogon.

## Подготовить один раз

- Главная УН: RDP 185.82.25.17:44389; центр внутри сети http://192.168.88.252:34001; исходники C:\script_factory.
- На цели: Node.js 24+, действующий .env и настроенный WinRM с доступом администратора.
- На главной УН: публичный ключ **существующей доверенной пары** в C:\Deploy\release-public.pem. Приватный ключ на целевые УН не передаётся.
- Для WinRM HTTP используются порт 5985 и Negotiate с явными учётными данными. Если нет Kerberos/домена, на главной УН заранее настройте TrustedHosts только для нужных адресов согласно политике вашей сети. Скрипт не устанавливает TrustedHosts=* и не открывает порты автоматически. Для WinRM HTTPS задайте -UseSSL (по умолчанию порт 5986), для своего порта — -WinRMPort.
- Аккаунт запуска должен иметь доступ к индивидуальным enrollments. Каталог содержит секреты: не публикуйте его и не добавляйте в Git.

## Пилот на Нефедове (192.168.88.249)

Откройте PowerShell на главной УН. Копируйте блок целиком:

```powershell
& C:\script_factory\windows\deploy-fleet-agents.ps1 `
  -CsvPath C:\Deploy\nodes.csv `
  -CentralUrl http://192.168.88.252:34001 `
  -ReleasePublicKey C:\Deploy\release-public.pem `
  -EnrollmentDirectory C:\Deploy\enrollments `
  -OnlyUnId un-nefedov-test `
  -ResultCsv C:\Deploy\agent-results.csv
```

Токен администратора центра запрашивается скрытым вводом, если FLEET_ADMIN_TOKEN ещё не задан в сеансе. Windows-логин и пароль администратора целевых УН запрашиваются один раз через Get-Credential; одинаковые учётные данные используются для выбранных УН. Для уже подготовленного PSCredential можно явно передать -Credential. Пароли в CSV и JSON не записываются.

Для всех УН из CSV уберите `-OnlyUnId un-nefedov-test`. Для нескольких выбранных используйте `-OnlyUnId un-nefedov-test,un-valliulin-test`. Рабочий каталог PowerShell значения не имеет. Цели обрабатываются последовательно; ошибка одной УН не мешает попытке на следующей. После завершения возвращаются результаты по UN_ID, каноническому ID, сетевому адресу и причине; при ошибках общий вызов завершается ошибкой.

## Что происходит автоматически

1. CSV преобразуется во временный JSON; выбираются указанные UN_ID.
2. Проверяются центр и незавершённые обновления. Новые УН регистрируются, существующие с действующим локальным ключом переиспользуются; канонический ID сохраняется.
3. По WinRM проверяются права администратора, Node и **UN_ID фактической .env целевой УН**, прежде чем передавать ключ агента. Несовпадение блокирует установку.
4. В уникальный защищённый временный каталог цели передаются только нужные исходники, индивидуальный JSON и публичный ключ.
5. Штатный установщик создаёт агент в C:\ProgramData\ScriptFactoryAgent и задачу ScriptFactory-Fleet-Agent от SYSTEM, запускает её и настраивает запуск при включении Windows. Не требуется входить в robot по RDP.
6. Проверяется **новый heartbeat** после запуска, затем api_ready. Статус ready означает, что агент связался с центром и сообщил о готовности API. Это не проверка настройки ЭЦП/СБИС и не результат выполнения браузерного задания.
7. Временная копия JSON на цели удаляется; рабочая конфигурация остаётся в защищённом каталоге установленного агента. При обрыве WinRM удаление может не состояться — скрипт покажет путь для последующей очистки.

По умолчанию контакт ожидается до 180 секунд на каждую УН; изменить можно через -WaitSeconds. В ожидании выводятся сообщения. Для одного лишь плана добавьте **-PlanOnly**: регистрация, смена ключей и WinRM-установка не выполняются.

## Повторный запуск и защита от старого обновления

Повторяйте ту же команду с тем же каталогом enrollments. Если установленный агент имеет ту же конфигурацию и публичный ключ, скрипт не переустанавливает его: работающая задача сохраняется, остановленная запускается. Затем снова проверяется свежий контакт. Это установка/запуск агента, а не автоматическое обновление его собственного кода.

Если индивидуальный ключ потерян/отозван, используйте -RecoverExisting только для осознанного перевыпуска: старый ключ перестанет действовать. Установленный агент с отличающейся конфигурацией скрипт не перезаписывает автоматически; для его перенастройки требуется штатное обслуживание в свободный момент. Неполная существующая установка, другой владелец задачи или другой публичный ключ также не удаляются вслепую.

**Если у цели уже есть queued-операция, установка по умолчанию блокируется ещё до регистрации/подключения.** В текущем пилоте это защищает от немедленного получения старого релиза 0.11.1. Отмените устаревшие ожидающие операции в панели. Если вы проверили пакет и действительно хотите, чтобы он мог начаться сразу после запуска агента, добавьте -AllowQueuedDeployments. Этот флаг не разрешает вмешательство в уже назначенную/выполняемую операцию или recovery_required. Скрипт не отменяет общую раскатку за другие УН автоматически.

## Где смотреть причину неготовности

- Ошибка WinRM: проверьте адрес/порт/TrustedHosts, права и учётные данные. API-порт 33001 и RDP-порт не являются WinRM-портами.
- UN_ID mismatch: сверяйте CSV, подготовленный EnvFile и действующую .env именно этой УН; ключ не передаётся до проверки.
- AGENT_NO_HEARTBEAT: проверьте задачу ScriptFactory-Fleet-Agent и C:\ProgramData\ScriptFactoryAgent\data\agent-err.log на цели, доступность central_url из неё и индивидуальный ключ.
- AGENT_CONNECTED_API_NOT_READY: агент доступен, но сообщил о неготовности локального API; проверяйте процесс API, .env и локальный /health.
- Status=ready: установка и связь подтверждены; затем отдельно выпускайте актуальный пакет и создавайте раскатку.

## Проверка реализации

Проверены синтаксис в Windows PowerShell 5.1, защитные проверки очереди/идентичности/конфигураций и сценарии с подменёнными WinRM/HTTP-адаптерами. Массовая установка на рабочие УН в рамках этой доработки не запускалась. Начинайте с одной пилотной УН.
