# Установка, обновление и восстановление одной командой

Запускайте `windows/deploy-one-un.ps1` из отдельного каталога доставки, например `C:\Deploy`, а не из заменяемого приложения. Рядом должен находиться `deployment-state.ps1` из того же релиза. Node.js 24+, браузер, учётная запись robot и компоненты ЭЦП должны быть подготовлены заранее. Запуск — в повышенной Windows PowerShell 5.1.

Сначала приостановите новые задания из 1С, дождитесь завершения текущих и согласуйте замену локально изменённого кода. Не отключайте рабочую УН для этой проверки.

```powershell
# Распаковать инструменты вне каталога приложения.
Expand-Archive C:\Deploy\release.zip C:\Deploy\release-tools
$sha256 = (Get-FileHash C:\Deploy\release.zip -Algorithm SHA256).Hash
& C:\Deploy\release-tools\windows\deploy-one-un.ps1 `
  -PackageZip C:\Deploy\release.zip `
  -ExpectedVersion '0.13.1' -ExpectedSha256 $sha256 `
  -ProjectPath C:\script_factory -EnvFile C:\Deploy\node.env `
  -Port 33001 -ConfirmNoNewJobs -ConfirmReplaceCode
```

Версия должна соответствовать выбранному архиву. Получение хеша на месте проверяет неизменность архива между доставкой и запуском; для контроля источника сверяйте его с согласованным релизом. Каталог доставки и env защитите от доступа посторонних. Не включайте секреты в Git.

| Состояние | Действие |
| --- | --- |
| Каталога нет | Новая установка с переданным EnvFile. |
| Каталог пустой или отсутствуют/повреждены основные файлы, JSON метаданных, обязательные поля конфигурации или каталог зависимостей | Подготовка новой версии и зависимостей, затем замена каталога с сохранением старого в резервной копии. |
| Файлы и конфигурация присутствуют, задача API ссылается на проект | Существующий update-one-un.ps1: проверка готовности и пустой очереди, резервная копия, обновление, проверка и откат при ошибке. |
| Файлы присутствуют, задача отсутствует | Переустановка приложения и задач с сохранением конфигурации и данных. |

Тайм-аут API, отсутствие RDP-сеанса robot или неготовый браузер не доказывают повреждение файлов. Если существующий механизм обновления не может подтвердить готовность API/worker, он остановится с ошибкой; удаление исправной установки не запускается. Задачи, принадлежащие другому каталогу, занятый порт и оставшиеся процессы приложения также блокируют замену.

## Что сохраняется

Существующий `.env` имеет приоритет над доставленным EnvFile, включая секреты, UN_ID, порт, пользователя worker и DATA_DIR. Некорректную существующую конфигурацию нужно исправить: автоматически подменять её чужими значениями нельзя. При отсутствии `.env` используется EnvFile.

Старый каталог целиком перемещается в `C:\ScriptFactory-backups\replaced-<дата>-<id>`. Поэтому повреждённые файлы больше не участвуют в запуске, но конфигурация, локальные дополнения и данные остаются доступны для восстановления. Внешний DATA_DIR не перемещается; внутренний DATA_DIR копируется в новую установку. Каталоги отчётов вне приложения не затрагиваются. Не размещайте входящие отчёты среди файлов исходного кода.

Архив проверяется до остановки задач; зависимости новой установки также готовятся заранее. После остановки проверяется отсутствие процессов и незавершённых заданий в state.sqlite. Повреждённая/нечитаемая база блокирует замену. Флаги не разрешают игнорировать занятую очередь.

После переустановки проверяется `/live`: версия и UN_ID. Готовность браузера проверяйте отдельно через `/health` под robot. Автозапуск Saby устанавливается отдельно командой `windows/install-saby-task.ps1`, как в основной инструкции.

Если ошибка произошла после замены каталога, обе версии и данные сохраняются; задачи нового запуска отключаются, сообщение указывает пути. Автоматического копирования старой базы поверх новых данных нет. До повторной попытки выясните причину и выберите правильный каталог для восстановления. Старые резервные копии автоматически не удаляются.

Проверить только состояние файлов, без изменений:

```powershell
. C:\Deploy\release-tools\windows\deployment-state.ps1
Get-SFInstallationState C:\script_factory
```

Это проверка структуры, а не подтверждение работоспособности API, браузера или ЭЦП. Полная приёмка — по [инструкции установки](01-install-one.md).

Изолированные Windows-тесты: `& .\test\windows\deploy-one-un.tests.ps1 -Repository (Get-Location).Path`. Они используют временные каталоги и заглушки задач, процессов и сетевых вызовов. Проверки SQLite дополнительно требуют Node.js 24+.
