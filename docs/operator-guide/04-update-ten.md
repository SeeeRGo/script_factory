# Обновить десять УН до релиза из Git

Используйте оркестратор: центральный сервер, десять зарегистрированных агентов и API 0.11.0+ уже должны быть установлены. Первичный переход с 0.9.x выполняется вручную по инструкции 03; новый агент не заменяет этот bootstrap.

## Один раз подготовить

Разверните центр, настройте HTTPS и установите публичный ключ подписи на центр/агенты по [полной инструкции](../project-guide/11-fleet-updates.md). Приватный ключ держите только на компьютере выпуска. Задайте каждому агенту индивидуальный токен.

## Выпустить пакет из Git

На компьютере выпуска:

```powershell
git fetch origin
npm run fleet:release -- build --ref ТОЧНЫЙ_SHA_НОВОГО_РЕЛИЗА --key C:/ScriptFactorySigning/release-private.pem --out C:/ScriptFactoryReleases
$env:FLEET_ADMIN_TOKEN = Read-Host 'Токен администратора оркестратора' -MaskInput
npm run fleet:release -- publish --url https://fleet.company.ru --manifest C:/ScriptFactoryReleases/ID.json --zip C:/ScriptFactoryReleases/ID.zip
Remove-Item Env:\FLEET_ADMIN_TOKEN
```

`Read-Host -MaskInput` требует PowerShell 7; в Windows PowerShell 5.1 передайте переменную из корпоративного хранилища секретов, не вставляйте токен в файл/историю. ID.json/ID.zip замените на имена, выданные build. Версия должна быть новее установленной. Сборка использует зафиксированный commit, проверяет состав и подписывает ZIP.

## Запустить и принять раскатку

1. В панели выберите готовый релиз и ровно десять УН. Укажите окно обновления.
2. Первой поставьте одну пилотную УН, canary_count=1, batch_size=1.
3. Агент закроет приём новых заданий, дождётся очереди/callback/скачиваний, заблокирует выключение на время обслуживания и выполнит обновление.
4. После успешного пилота продолжится выдача остальным. Для первой массовой проверки сохраняйте batch_size=1; повышайте после приёмки. Оркестратор контролирует также глобальный FLEET_MAX_CONCURRENT.
5. При ошибке дальнейшая выдача приостанавливается. Проверьте причины, откат и состояние УН, затем явно повторите/продолжите. Не считайте recovery_required успешным откатом.
6. Для каждой из десяти УН проверьте succeeded, новую версию и свежий heartbeat. На пилоте дополнительно выполните браузерный smoke-тест. Автоматическая проверка оркестратора проверяет worker/файлы, но не лицензию или каждую ЭЦП СБИС.

Выключенная УН получит команду после включения; оркестратор не включает гипервизор. Недоступная пилотная УН задерживает группу. Снятие обслуживания возвращает прежнюю политику выключения.

Если оркестратор пока не развёрнут, допустимо последовательно обновить десять УН помощником из инструкции 03, сохраняя отдельный backup/результат каждой. Это административная пакетная процедура, а не автоматическая раскатка оркестратором.
