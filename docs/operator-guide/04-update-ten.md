# Обновить десять УН до релиза из Git

**0.17.0+:** общий установщик и запуск нового API автоматически согласуют код агента; для первой регистрации передайте индивидуальный JSON и публичный ключ. [Инструкция](16-integrated-agent.md).

Перед получением кода настройте [доступ к закрытому репозиторию на компьютере выпуска](12-private-repository.md). На УН GitHub-ключи не требуются.

Используйте оркестратор: центральный сервер, десять зарегистрированных агентов и API 0.11.0+ уже должны быть установлены. Первичный переход с 0.9.x выполняется вручную по инструкции 03; новый агент не заменяет этот bootstrap.

## Один раз подготовить

Разверните центр, выберите HTTP во внутренней сети либо HTTPS и установите публичный ключ подписи на центр/агенты по [полной инструкции](../project-guide/11-fleet-updates.md). Приватный ключ держите только на компьютере выпуска. Задайте каждому агенту индивидуальный токен.

## Выпустить пакет из Git

На компьютере выпуска (замените 192.168.88.10:34001 адресом своего центра; HTTPS также поддерживается):

```powershell
& C:\script_factory\windows\publish-fleet-release.ps1 `
  -SourceDirectory C:\ScriptFactorySource `
  -CentralUrl http://192.168.88.252:34001
```

Укажите в `-SourceDirectory` корень Git-клона, в котором проходит `git ls-remote origin refs/heads/main`. Без параметра используется каталог проекта рядом со скриптом. Обычная команда сначала получает актуальную ветку origin/main из Git, затем собирает именно полученный коммит и автоматически передаёт созданные manifest/ZIP в публикацию. Локальный HEAD и незакоммиченные файлы не определяют версию пакета. Рабочая папка, .env и запущенные процессы не изменяются; git pull/checkout для выпуска не требуется. Перед публикацией выводятся версия и полный хеш коммита. Если сеть, доступ к приватному репозиторию или ветка недоступны, сборка прекращается без использования старой локальной версии. При необходимости задайте -SigningKey и -OutputDirectory. Токен центра запрашивается скрытым вводом, совместимым с PowerShell 5.1.


## Запустить и принять раскатку

1. В панели выберите готовый релиз и ровно десять УН. Укажите окно обновления.
2. Первой поставьте одну пилотную УН, canary_count=1, batch_size=1.
3. Агент закроет приём новых заданий, дождётся очереди/callback/скачиваний, заблокирует выключение на время обслуживания и выполнит обновление.
4. После успешного пилота продолжится выдача остальным. Для первой массовой проверки сохраняйте batch_size=1; повышайте после приёмки. Оркестратор контролирует также глобальный FLEET_MAX_CONCURRENT.
5. При ошибке дальнейшая выдача приостанавливается. Проверьте причины, откат и состояние УН, затем явно повторите/продолжите. Не считайте recovery_required успешным откатом.
6. Для каждой из десяти УН проверьте succeeded, новую версию и свежий heartbeat. На пилоте дополнительно выполните браузерный smoke-тест. Автоматическая проверка оркестратора проверяет worker/файлы, но не лицензию или каждую ЭЦП СБИС.

Выключенная УН получит команду после включения; оркестратор не включает гипервизор. Недоступная пилотная УН задерживает группу. Снятие обслуживания возвращает прежнюю политику выключения.

Если оркестратор пока не развёрнут, допустимо последовательно обновить десять УН помощником из инструкции 03, сохраняя отдельный backup/результат каждой. Это административная пакетная процедура, а не автоматическая раскатка оркестратором.
