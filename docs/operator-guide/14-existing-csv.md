# Главный узел: регистрация УН из существующего C:\Deploy\nodes.csv

Этот порядок относится к схеме заказчика:

| Назначение | Адрес/путь |
| --- | --- |
| Подключение администратора к главной УН | RDP 185.82.25.17:44389 |
| HTTP оркестратора внутри сети | http://192.168.88.252:34001 |
| Проект с package.json и scripts | C:\script_factory |
| Существующий список целевых УН | C:\Deploy\nodes.csv |
| Подготовленные конфигурации целевых УН | Пути EnvFile из CSV |
| Производный инвентарь регистрации | C:\Deploy\nodes.json |
| Индивидуальные конфигурации агентов | C:\Deploy\enrollments\<id>.json |

44389 — RDP-порт, его не подставляют в --url. Главная УН не добавляется в список целей автоматически: преобразуются только строки CSV. Скрипт не подключается к рабочему столу, не меняет AutoAdminLogon, не устанавливает API и не запускает обновление целевых УН.

## Почему возникла ошибка

Сообщение ENOENT open C:\Deploy\nodes.json означает, что npm уже нашёл проект и запустил fleet:enroll, но входной JSON отсутствует. nodes.csv и nodes.json — разные форматы, переименование файла не конвертирует его.

Существующий CSV имеет колонки Computer,EnvFile. Для первоначальной установки это адрес УН и путь подготовленного env. Для регистрации оркестратору нужны id, un_id, адрес API и пути агента. Новый windows/convert-fleet-inventory.ps1 преобразует CSV в JSON, читая из каждого EnvFile только UN_ID и PORT. Пароли, API_KEY и остальные поля env в JSON не копируются.

## 1. Подготовить исходники и проверить CSV

На главной УН используйте комплект проекта **0.15.0+**, содержащий windows/convert-fleet-inventory.ps1. Обновляйте файлы проекта штатной процедурой, не накладывая git pull поверх работающего API. Процесс оркестратора может продолжать работать; конвертер создаёт только инвентарь регистрации.

CSV менять или повторно заполнять JSON вручную не нужно. Пример структуры (адрес и имя файла здесь учебные):

```csv
Computer,EnvFile
192.168.88.100,C:\Deploy\env\un-001.env
```

Каждый EnvFile должен существовать **на главной УН** и содержать UN_ID, совпадающий с действующей конфигурацией соответствующей целевой УН, а также её PORT. Это подготовленные конфигурации, а не удалённые пути Windows. По CSV скрипт не пытается угадывать UN_ID из IP. При несовпадении подготовленного EnvFile с реальной УН исправьте данные до регистрации.

## 2. Синхронизировать полный CSV одной командой (0.15.0+)

На главной УН обновите исходники проекта до 0.15.0+. Запускайте PowerShell от администратора. Каталог запуска значения не имеет; npm и ручное создание nodes.json не нужны:

```powershell
& C:\script_factory\windows\sync-fleet-enrollment.ps1 `
  -CsvPath C:\Deploy\nodes.csv `
  -CentralUrl http://192.168.88.252:34001 `
  -OutputDirectory C:\Deploy\enrollments
```

Токен администратора центра запрашивается скрытым вводом, если FLEET_ADMIN_TOKEN ещё не задан. CSV должен содержать **весь нужный список**, включая ранее зарегистрированные УН. Не удаляйте успешные строки и готовые конфигурации после частичного запуска.

Скрипт сам преобразует CSV во временный инвентарь, проверяет центр и существующие JSON. Сопоставление выполняется по UN_ID, поэтому запись `miheev-test` с UN_ID `un-miheev-test` сохраняет прежний node_id. Новые УН регистрируются, существующие с действующим локальным ключом переиспользуются. central_url берётся из -CentralUrl и обновляется в выходных JSON; **RDP 185.82.25.17:44389 к нему отношения не имеет**. Для агентов используется внутренний HTTP-адрес главной УН: http://192.168.88.252:34001.

Для просмотра плана без регистрации/смены ключей добавьте `-PlanOnly`. Действия: create — создать, reuse — переиспользовать, blocked — отсутствует действующий локальный ключ, recover — восстановить ключ.

Если ключ потерян, отозван или JSON ещё не был сохранён после регистрации через панель, повторите ту же команду с `-RecoverExisting`. Этот флаг перевыпускает **только недостающие/неработающие ключи**. Действующие ключи не меняются. После восстановления передайте новый JSON соответствующему установленному агенту: старый ключ работать перестанет. ID и история УН сохраняются. Без флага вся операция останавливается до новых регистраций, если требуется восстановление.

JSON сохраняются в OutputDirectory, изменённая предыдущая конфигурация — рядом с расширением .bak. Каталог содержит секреты: не загружайте его в Git и не прикладывайте к переписке. Повторяйте запуск с тем же каталогом. Одновременные запуски блокируются файлом .enrollment.lock; после аварийного завершения сначала убедитесь, что процесс завершён, затем удалите блокировку. Если сбой произошёл после выдачи ключа центром, но до сохранения JSON, используйте -RecoverExisting: получить исходный ключ из центра невозможно.

Скрипт не угадывает идентичность по IP и не исправляет ошибочные UN_ID в исходных env. Конфликт id с другим UN_ID и неоднозначные локальные JSON требуют проверки исходных данных. Для работы не требуется обновление процесса центра: проверка ключа использует существующий защищённый API без записи heartbeat.

## 3. Собрать и опубликовать релиз без заглушек

```powershell
& C:\script_factory\windows\publish-fleet-release.ps1 `
  -CentralUrl http://192.168.88.252:34001
```

Начиная с **0.15.1** команда сама получает актуальный **origin/main** из Git и собирает полученный коммит. Старый локальный HEAD больше не является источником обычной сборки. Незакоммиченные файлы и .env не изменяются и в релиз не попадают. Перед публикацией показываются версия и полный хеш. При недоступном Git сборка останавливается; старый пакет автоматически не публикуется.

Один раз установите утилиты 0.15.1+ на главную УН. Нужен Git-клон с remote origin, указывающим на `git@github.com:companyZ-1C/script_factory.git`, и доступом этой Windows-учётной записи к приватному репозиторию. Проверьте remote командой `git -C C:\script_factory remote -v`. Если origin отсутствует или указывает не туда, исправьте его до запуска. Одного распакованного ZIP без .git недостаточно. Закрытый ключ доступа к Git должен быть настроен заранее; команда не ожидает интерактивного ввода пароля SSH.

Для другой удалённой ветки/репозитория используются -Remote и -Branch. Для осознанного выпуска конкретной уже имеющейся ревизии добавьте -Ref с тегом/хешем: **это явный режим без получения свежей ветки**; -Ref HEAD снова означает локальный HEAD. Не вводите буквально КОММИТ_РЕЛИЗА или ID.json. Выпуск не запускает установку на УН: после публикации выберите новый релиз в панели, старые раскатки сохраняют ранее выбранный пакет.

Ключ подписи по умолчанию C:\ScriptFactorySigning\release-private.pem, каталог результата C:\ScriptFactoryReleases; при необходимости задайте -SigningKey и -OutputDirectory. Используйте существующую доверенную пару ключей, не создавайте новую для каждого релиза. Скрипт передаёт в публикацию именно manifest и ZIP только что выполненной сборки. Раскатка автоматически не запускается: после публикации выберите УН и запустите её в панели.

## 5. Перейти к установке агентов и обновлению API

Регистрация создаёт запись в центре и индивидуальный JSON, но не устанавливает/обновляет API на перечисленных IP. Для автоматической передачи файлов, установки и проверки контакта используйте [массовый запуск с главной УН](15-agent-bootstrap.md). Ручной способ остаётся в [инструкции оркестратора](../project-guide/11-fleet-updates.md). Затем выпустите подписанный релиз и выберите цели обновления по [инструкции](04-update-ten.md). nodes.json не загружается в форму «Пакет релиза»: туда нужны manifest и ZIP.

Для уже установленных API сохраните их UN_ID, ключи, пути и пользовательский сеанс. Переустановка с нуля и изменение AutoAdminLogon для регистрации/конвертации не требуются.
