# Откат и восстановление после сбоя обновления

1. Приостановите раскатку. В «Результаты по УН» → «Диагностика / журналы» найдите адрес, UN_ID и ID операции. На проблемной УН проверьте протокол `C:\ProgramData\ScriptFactoryAgent\data\<ID операции>.result.json.log` и, если он появился, `<ID операции>.rollback.json.log`. При другом `data_dir` используйте каталог из конфигурации агента.
2. Если установка ещё идёт, дождитесь её завершения. При `rolled_back` проверьте прежнюю версию, UN_ID и `ready: true` через локальный `/health`. Если обслуживание снято и API готов, повторный откат не нужен. При `failed` выясните по протоколу, менялись ли файлы. При `recovery_required` исход установки неизвестен. Пока он не выяснен, не запускайте второй установщик и не удаляйте журнал агента.
3. Если нужно вернуть прежнюю версию API вручную, приостановите новые задания из 1С и дождитесь пустой очереди. Найдите резервную копию по протоколу или результату установщика. Сверьте пути, задачи и прежнюю версию в её `manifest.json`. Восстановите файлы и при необходимости зависимости и задачи по [процедуре ручного отката](../project-guide/04-update-one-un.md#6-ручной-откат-после-неудачной-проверки). Сохраните текущий `DATA_DIR`, чтобы не потерять новые задания и результаты. Если подходящей копии нет или состояние очереди неизвестно, передайте ID операции и протокол администратору сопровождения.
4. После запуска API и worker сверьте UN_ID и ожидаемую версию. Если обслуживание ещё активно, сверьте владельца с операцией. С действующим `X-API-Key` вызовите `POST /api/v2/system/maintenance/verify` с JSON `{"owner":"fleet-<ID операции>"}`. После `verified: true` и проверки версии и UN_ID вызовите `POST /api/v2/system/maintenance/end` с тем же JSON. При другой операции-владельце или неудачной проверке оставьте обслуживание включённым до выяснения причины.
5. Убедитесь, что локальный `/health` возвращает `ready: true`, и дождитесь свежего контакта агента с центром. Для `recovery_required` нажмите «Подтвердить восстановление». Кнопка фиксирует результат проверки администратора. Для открытой раскатки нажмите «Повторить», затем «Продолжить». При истёкшем окне сначала измените его. Для отменённой или завершённой раскатки создайте новую.

Если сбой произошёл **при замене агента** в 0.17.0+, проверьте `C:\ProgramData\ScriptFactoryAgent\agent-sync-result.json` и `agent-sync.log`. При ошибке система пытается вернуть прежний код и задачу агента. Сверьте его версию и свежий контакт в панели. Версию и готовность API проверьте отдельно. Если старый агент прерывает установку до запуска нового API, сначала обновите его через [массовый bootstrap](15-agent-bootstrap.md). Подробнее см. [обновление агента](16-integrated-agent.md).
