# Профили конфигурации и секреты в оркестраторе

API 0.13.0 и обновлённый агент (agent_version=2) добавляют хранение профилей, индивидуальных параметров УН и секретов. Оркестратор по-прежнему устанавливается отдельно, один на парк. На каждой УН работает исходящий агент. После обновления центрального сервера один раз обновите сам агент штатным установщиком в свободное окно: обновление API не заменяет независимый агент автоматически.

## 1. Включить хранилище секретов

На сервере создайте **отдельный** каталог ключей, не внутри каталога данных/резервных копий базы:

```bash
npm run fleet:config -- keygen --out /etc/script-factory/keys/fleet-master.key
```

Команда не перезаписывает существующий ключ. Укажите в окружении центрального сервиса:

```dotenv
FLEET_MASTER_KEY_FILE=/etc/script-factory/keys/fleet-master.key
```

Дайте пользователю сервиса чтение ключа. Например, если команду выполнял root, а systemd работает от sf-fleet:

```bash
sudo chown root:sf-fleet /etc/script-factory/keys /etc/script-factory/keys/fleet-master.key
sudo chmod 750 /etc/script-factory/keys
sudo chmod 640 /etc/script-factory/keys/fleet-master.key
sudo systemctl restart script-factory-fleet
```

Это новый ключ AES-256-GCM для секретов, он отличается от ключей подписи ZIP. В SQLite секреты и зафиксированные пакеты конфигураций шифруются. Значение секрета не возвращается в обзоре/предпросмотре; в журнале сохраняются ID и номер редакции. Храните резервную копию master key отдельно от БД. Потеря ключа означает потерю возможности расшифровать секреты. Не заменяйте master key новым файлом для обычной смены пароля: пароль меняется под его ID в панели. Копию SQLite делайте штатным резервным копированием SQLite либо при остановленном центре; ключ храните и восстанавливайте отдельно. При несовпадающем ключе запуск с vault останавливается. Без ключа прежние обновления релизов доступны, а управление конфигурациями заблокировано.

Публикуйте сервер только через HTTPS; на УН настройте доверие корпоративному УЦ для Node под SYSTEM. Администратор центра имеет доступ ко всему парку и может выгрузить секреты при первичном внедрении: ограничьте доступ к панели корпоративной сетью/VPN и выдавайте административный доступ только уполномоченным сотрудникам. Отдельных ролей/разграничения доступа по группам в этой версии нет.

## 2. Зарегистрировать УН и заполнить адреса

У каждой записи есть постоянный ID агента, уникальный UN_ID, название и группа. В карточке «Адреса и название УН» задайте:

* network_address — внутренний IP или DNS Windows-УН;
* rdp_address — адрес подключения администратора, например gateway.example.org:42389;
* api_address — адрес HTTP API для 1С, например http://192.168.10.11:33001;
* display_name — понятное название, например «Тестовая УН 1».

Ни один из этих адресов не заменяет UN_ID и не меняет пробросы/Firewall. api_url в локальном agent.config.json остаётся loopback-адресом API на этой же машине. Агент отдельно сообщает наблюдаемые имя Windows и локальные IP: это диагностика, а не автоматическая замена адресов карточки.

Для поиска используйте поле «Поиск УН или адреса»; оно ищет по ID, UN_ID, названию, IP, RDP и API. Кнопка «Выбрать показанные» отмечает строки после фильтра группы/поиска.

Адреса видны в таблице УН и результатах операций. Операция хранит снимок UN_ID, названия, сетевого адреса, RDP и API на момент создания: последующее редактирование карточки не переименовывает старый сбой.

Для десяти/трёхсот УН можно использовать JSON-инвентарь `fleet/nodes.example.json` и `npm run fleet:enroll`; поддержаны display_name, network_address, rdp_address и api_address. Индивидуальные токены агентов выдаются один раз и сохраняются CLI в защищённые enrollment-файлы.

## 3. Внести секреты

В форме «Секрет» создайте ID и введите значение. Например:

| ID | Что хранить |
| --- | --- |
| api-common | API_KEY для согласованной группы УН |
| web-un-001 | WEB_PASSWORD конкретной УН |
| callback-user | CALLBACK_AUTH_USERNAME |
| callback-password | CALLBACK_AUTH_PASSWORD |
| deploy-password | Пароль административной Windows-учётной записи для первичной установки |

Пароль повторно не показывается. Чтобы заменить, сохраните новое значение под тем же ID. Повышается revision; уже созданные операции сохраняют свою зафиксированную конфигурацию, ротация секрета их не изменяет. Для распространения нового значения создайте новое применение профиля. Пароль для административного WinRM-доступа не передаётся работающему агенту и не используется для автологина robot.

Чувствительные env-поля задаются только через secret_refs. Включая BROWSER_OPTIONS_JSON: внутри него могут быть реквизиты прокси. Не помещайте пароли внутрь обычных значений других env-полей, названий профилей, адресов или комментариев.

## 4. Создать общий профиль

Пример обычных env в JSON, все значения строками:

```json
{
  "PORT": "33001",
  "MAX_PARALLEL_JOBS": "1",
  "DEFAULT_JOB_TIMEOUT_MS": "300000",
  "JOB_RETENTION_DAYS": "7",
  "FILESYSTEM_ALLOWED_ROOTS": "C:/",
  "CALLBACK_ALLOWED_ORIGINS": "https://callback.example.org",
  "POWER_ENABLED": "false",
  "POWER_BACKGROUND_ENABLED": "false"
}
```

Для fileserver нужно полное имя общей папки, например `C:/;\\fileserver\Reports` в env или `"C:/;\\\\fileserver\\Reports"` внутри JSON. Права доступа Windows выдаются отдельно пользователю worker.

Пример secret_refs:

```json
{
  "API_KEY": "api-common",
  "CALLBACK_AUTH_USERNAME": "callback-user",
  "CALLBACK_AUTH_PASSWORD": "callback-password"
}
```

Общие параметры первичной установки задаются отдельным bootstrap, например:

```json
{
  "project_path": "C:/script_factory",
  "env_file": "C:/script_factory/.env",
  "windows_username": "DOMAIN\\deploy",
  "windows_password_ref": "deploy-password"
}
```

При отсутствии worker_account установщик выбирает локального COMPUTERNAME\robot. Если пользователь другой, укажите полное имя в индивидуальной карточке. При нестандартном пути Saby задайте saby_executable_path. Node, браузер, криптокомпоненты, Saby и пользователь уже должны быть подготовлены; Windows-пароль развёртывания не создаёт ЭЦП или интерактивный сеанс.

## 5. Назначить профиль группе и индивидуальные отличия

Выберите УН в таблице, откройте сохранённый профиль и нажмите «Назначить открытый профиль выбранным УН». Это меняет только назначение: env на УН ещё не применяется, а существующие индивидуальные переопределения сохраняются.

Для конкретной УН в карточке можно переопределить env, ссылки на секреты и bootstrap. Например, общий API_KEY, а индивидуальный WEB_PASSWORD:

```json
{"WEB_PASSWORD":"web-un-001"}
```

Приоритет: общий профиль → индивидуальные env/secret_refs. Null в обычном env удаляет ключ при применении. API_KEY и WEB_PASSWORD нельзя очистить. UN_ID берётся из реестра и никогда не наследуется от общего профиля. Смена UN_ID работающей УН не выполняется этим модулем.

Нажмите «Показать настройки». Пароли будут обозначены `[secret]`. Предпросмотр показывает желаемые значения, а не считывает текущий env с УН. Если после предпросмотра изменён профиль, карточка или используемый секрет, применение потребует нового просмотра.

## 6. Первичная установка на одну или десять УН

Для новой машины нажмите «Скачать для первичной установки», явно подтвердив выгрузку с паролями. Или используйте CLI:

```powershell
npm run fleet:config -- bootstrap --url https://fleet.company.ru --nodes un-001,un-002 --out C:/ProtectedDeploy/bootstrap
```

FLEET_ADMIN_TOKEN передайте из защищённого хранилища окружению процесса. CLI сохраняет индивидуальные env и metadata JSON в защищённый каталог; не печатает секреты. Браузер скачивает один fleet-bootstrap.json с массивом nodes. **Оба варианта содержат открытые секреты**, в том числе Windows-пароль при заданной ссылке; храните их только в защищённом месте, не в Git и не в общих папках. Событие выгрузки записывается в аудит.

Для установщика нужен браузерный bundle fleet-bootstrap.json. На Windows-контроллере с настроенным WinRM HTTPS:

```powershell
& .\windows\install-fleet-bootstrap.ps1 `
  -BundleFile C:\ProtectedDeploy\fleet-bootstrap.json `
  -ReleaseZip C:\Deploy\release.zip `
  -ExpectedSha256 'SHA256_СОГЛАСОВАННОГО_АРХИВА' `
  -EnrollmentDirectory C:\ProtectedDeploy\enrollments `
  -ReleasePublicKey C:\ProtectedDeploy\release-public.pem
```

Пакет должен содержать API 0.13.0+ и новые установщики. Скрипт обрабатывает УН последовательно, проверяет SHA локально и удалённо, создаёт индивидуальный env с UN_ID из реестра, устанавливает задачи API/worker/Saby и при указанных enrollment-файлах — агента. На первом сбое останавливается и указывает node_id, UN_ID и host. Существующую установку не перезаписывает: для неё используется обновление. Он не включает WinRM и не отключает проверку TLS. Если Windows-логин/пароль не заданы в карточке, запросит административные реквизиты.

EnrollmentDirectory содержит ранее выданные `un-001.json`, `un-002.json` от fleet:enroll. Их UN_ID и пути должны совпадать с карточками; секрет агента автоматически не перевыпускается при каждой выгрузке. Без EnrollmentDirectory устанавливаются только API/worker/Saby, агент устанавливается отдельно. CLI bootstrap также пишет fleet-bootstrap.json в каталог выгрузки, поэтому этот файл можно использовать вместо браузерной загрузки.

После установки требуется вход robot, /health ready=true, безопасное браузерное задание и проверка RDP/перезагрузки. Затем проверьте строку агента в центре. Тестируйте сначала одну УН. Автоматический вход Windows и отправка реальных отчётов не включаются этой процедурой.

## 7. Применить настройки на работающих УН

Обновите API до 0.13.0 и независимый агент до версии 2. Выберите УН, сделайте предпросмотр, задайте окно, batch_size=1 и canary_count=1 для первого пилота. Нажмите «Применить показанные настройки».

Агент дожидается очереди, callback и скачиваний; блокирует выключение режимом обслуживания; получает только свой зафиксированный пакет; отключает задачи на время записи и сохраняет защищённый backup env и runtime-настроек. После перезапуска он проверяет health и фиксированный безопасный workflow. При неудачной проверке выполняется откат. При неизвестном исходе установка не повторяется автоматически, остаётся recovery_required и обслуживание для разбора по указанной УН.

Настройки MAX_PARALLEL_JOBS, DEFAULT_JOB_TIMEOUT_MS, JOB_RETENTION_DAYS, RETRY_* обновляются также в сохранённом app_config SQLite. Явно заданные POWER_* обновляют соответствующие переопределения питания. Остальные настройки очереди/питания сохраняются; задания, результаты и БД целиком не восстанавливаются поверх новых данных. Null для POWER_* удаляет его env-значение и сохранённое переопределение, возвращая default. После снятия обслуживания действует получившаяся политика питания: её включение может выключить свободную УН.

PORT, HOST и DATA_DIR в профиле допустимы для первичной установки. На работающей УН они пропускаются, если точно совпадают с фактами агента; при отличии требуется отдельное внедрение. EXECUTION_MODE, пользователь worker, секрет локального канала и задачи не меняются через env-патч. Смена Windows-пользователя/сети/каталога данных требует отдельного плана.

Релиз и конфигурация одной УН не могут применяться одновременно. Сохранение/назначение профиля само по себе не инициирует изменения. Дальнейшие УН не получают команду до успеха пилота; ошибки приостанавливают раскатку.

## API центра

Все маршруты администратора требуют учётную запись центра; ключ API отдельной УН не подходит.

| Метод | Назначение |
| --- | --- |
| POST /api/config/secrets | Создать/заменить секрет: id, value, expected_revision для замены |
| POST /api/config/profiles | Создать/изменить профиль: id, name, env, secret_refs, bootstrap, expected_revision |
| PUT /api/nodes/{id} | Изменить display_name/network_address/rdp_address/api_address с expected_revision |
| PUT /api/nodes/{id}/configuration | Профиль, индивидуальные env/secret_refs/bootstrap, expected_revision |
| POST /api/config/assign | Массово назначить profile_id, node_ids, expected_revisions |
| POST /api/config/preview | Предпросмотр node_ids, секреты скрыты |
| POST /api/config/rollouts | Применить node_ids, expected_versions из предпросмотра, batch_size, canary_count, окно |
| POST /api/config/bootstrap | Защищённая выгрузка node_ids, confirm_sensitive_export=true |

Пауза, продолжение, отмена ожидающих, повтор и подтверждение восстановления используют существующие маршруты раскаток. Старые пакеты конфигурации на повторе остаются прежними: для новых значений создайте новый rollout, а не повтор старого.

## Проверка и границы

Локальные интеграционные тесты проверяют шифрование, маскирование, изоляцию доступа агентов, фиксацию редакций, смену API-ключа, обновление сохранённых настроек и откат без изменения заданий. История адресов также проверяется тестом. Реальные WinRM-установка, Планировщик, restart/rollback на Windows Server 2022 требуют пилота. Эта документация не подтверждает завершённую промышленную приёмку 300 УН.
