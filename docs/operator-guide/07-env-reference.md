# Справочник .env

Для API 0.11.0. Шаблоны: [Windows](../../windows/.env.example), [общий](../../.env.example). Шаблон и встроенный default могут различаться: ориентируйтесь на явно заполненный рабочий env. Не все необязательные параметры присутствуют в шаблоне.

Изменения env применяются при запуске процессов; в broker перезапускайте API и worker при пустой очереди. Исключения по сохранённым настройкам очереди/питания описаны в [инструкции изменений](05-env-management.md). Boolean задавайте как true/false, время — в единицах из таблицы, JSON — одной строкой. Шаблоны не подставляют автоматически имя компьютера в произвольные значения.

## API и хранение

| Параметр | Назначение |
| --- | --- |
| API_KEY | Секрет заголовка X-API-Key для 1С/клиентов; не Windows-пароль |
| UN_ID | Уникальный идентификатор конкретной УН, не копировать одинаковым на парк |
| HOST | Адрес прослушивания API: 127.0.0.1 — локально, 0.0.0.0 — все IPv4-интерфейсы |
| PORT | HTTP-порт API; Windows-шаблон 33001, должен совпадать с установщиком и правилами сети |
| DATA_DIR | Каталог SQLite, результатов, артефактов и служебных журналов; смена пути сама данные не переносит |
| FILESYSTEM_ALLOWED_ROOTS | Разрешённые сценариям корни; на Windows разделитель `;`, на Linux `:`. Это разрешение API, оно не выдаёт права Windows |
| MAX_PARALLEL_JOBS | Начальная параллельность очереди; для СБИС обычно 1 |
| DEFAULT_JOB_TIMEOUT_MS | Начальный общий тайм-аут задания в миллисекундах; клиент может задать timeout_ms |
| JOB_RETENTION_DAYS | Начальный срок хранения завершённых заданий/результатов в днях |
| JOB_CLEANUP_INTERVAL_MS | Период фоновой проверки срока хранения, мс |
| RETRY_MAX_ATTEMPTS | Начальное максимальное число попыток, включая первую; повторяются только допускающие retry ошибки |
| RETRY_BACKOFF_MS | Начальная пауза между попытками, мс |
| PERSIST_DEBOUNCE_MS | Задержка объединения фоновых записей состояния в SQLite, мс; не задержка callback |
| SERVICE_BASE_URL | Внутренний базовый адрес для ссылок/операций сценариев, обращающихся к этому сервису; обычно loopback и правильный PORT |

MAX_PARALLEL_JOBS, DEFAULT_JOB_TIMEOUT_MS, JOB_RETENTION_DAYS и RETRY_* задают начальные значения. В существующей БД действуют сохранённые настройки GET/PUT /api/v2/system/config.

## API и worker

| Параметр | Назначение |
| --- | --- |
| EXECUTION_MODE | inline — общий процесс; broker — отдельные API под SYSTEM и пользовательский worker. Установщик сам переключает новую Windows-установку на broker |
| WORKER_ACCOUNT | Полное имя Windows-пользователя worker; заполняется установщиком |
| WORKER_AUTH_TOKEN | Индивидуальный секрет локального канала API/worker, минимум 32 символа; генерируется установщиком |
| WORKER_PORT | Локальный TCP-порт канала, по умолчанию PORT+1; не публиковать наружу |
| WORKER_TASK_NAME | Имя интерактивной задачи для установщика/обновлятора; не менять отдельно от задачи |
| WORKER_SESSION_ID | Служебный номер сеанса, передаётся launcher; руками в env обычно не задаётся |
| WORKER_STARTUP_MS | Срок рекомендации ждать входа/запуска worker, мс; default 120000 |
| WORKER_HEARTBEAT_MS | Период heartbeat, мс; default 3000 |
| WORKER_LOST_MS | Срок обнаружения потери связи, мс; default 15000, не меньше двух периодов heartbeat |
| WORKER_CANCEL_MS | Ожидание подтверждения остановки исполнения, мс; default 10000 |
| WORKER_MAX_MESSAGE_BYTES | Предел одного сообщения локального канала; default 16777216 байт |
| WORKER_MAX_PARALLEL_JOBS | Потолок одновременных исполнений worker, 1–100; также действует параллельность очереди API |

## Веб-интерфейс и callback

| Параметр | Назначение |
| --- | --- |
| WEB_LOGIN | Логин веб-панели API, не логин Windows/СБИС |
| WEB_PASSWORD | Пароль веб-панели API |
| WEB_SESSION_TTL_HOURS | Время жизни веб-сессии, часы |
| WEB_COOKIE_SECURE | Cookie только через HTTPS при true; без настроенного HTTPS вход может не сохраняться |
| CALLBACK_AUTH_TOKEN | Bearer-секрет обратного вызова 1С; не заполнять одновременно с Basic |
| CALLBACK_AUTH_USERNAME | Логин Basic для callback |
| CALLBACK_AUTH_PASSWORD | Пароль Basic для callback; используется вместе с USERNAME |
| CALLBACK_ALLOWED_ORIGINS | Допустимые origins через запятую, например https://dev.companya.ru, без пути обработчика. HTTP/HTTPS и порт имеют значение. Пустое значение отключает этот дополнительный список разрешений |

callback.url, max_attempts, backoff_ms, timeout_ms передаются в задании; это не те же параметры, что RETRY_* исполнения сценария. backoff_ms callback — интервал перед повторной попыткой, не пауза до первого callback.

## Браузер

| Параметр | Назначение |
| --- | --- |
| PUPPETEER_EXECUTABLE_PATH | Полный путь браузера, доступного пользователю worker |
| BROWSER_PRODUCT | Метка продукта, например yandex; сама браузер не устанавливает и путь не заменяет |
| BROWSER_HEADLESS | false — видимое окно, true — headless; ЭЦП/плагины проверяются в нужном режиме |
| BROWSER_STEP_DELAY_MS | Пауза между браузерными шагами, мс |
| BROWSER_HOLD_OPEN_MS | Пауза удержания браузера в поддерживаемых этапах завершения, мс; не ожидание отправки отчёта |
| BROWSER_CAPTCHA_WAIT_MS | Настройка ожидания CAPTCHA в браузерном исполнителе, мс; не автоматическое решение CAPTCHA |
| BROWSER_WINDOW_WIDTH | Ширина окна браузера |
| BROWSER_WINDOW_HEIGHT | Высота окна браузера |
| BROWSER_OPTIONS_JSON | Общие расширенные browser-настройки: профиль, окно, тайм-ауты, прокси и другие поддержанные поля |
| BROWSER_EXECUTABLE_ALLOWLIST | JSON-массив дополнительных разрешённых путей браузера, которые может выбрать сценарий |
| WORKFLOW_LIMITS_JSON | Общие ограничения JSON workflow: только поддержанные поля из отдельной инструкции |

Порядок переопределения и все вложенные поля JSON: [настройки браузера и limits](../project-guide/10-browser-settings.md). Произвольное имя внутри JSON не добавляет новую возможность API.

## noVNC

noVNC относится к отдельному просмотру Linux/Xvfb, не создаёт Windows-сеанс robot. Для демонстрации Windows используют тот же сеанс RDP, в котором работает worker.

| Параметр | Назначение |
| --- | --- |
| NOVNC_ENABLED | Включение интеграции просмотра; не устанавливает сам noVNC/Xvfb |
| NOVNC_BIND_HOST | Адрес привязки отдельного noVNC-сервера в средствах запуска |
| NOVNC_PORT | Порт отдельного noVNC-сервера, не API; в шаблоне 33303 |
| NOVNC_INTERNAL_PORT | Внутренний порт noVNC для прокси API |
| NOVNC_PUBLIC_PORT | Порт, показываемый клиенту в сведениях live_view |
| NOVNC_PUBLIC_URL | Публичная HTTPS-ссылка просмотра при внешнем прокси |
| NOVNC_PASSWORD | Пароль просмотра при поддержке соответствующим средством запуска |
| NOVNC_DISPLAY | X-display Linux, например :99 |
| NOVNC_GEOMETRY | Размер/глубина цвета Linux-дисплея, например 1440x900x24 |

## Проверка IP

| Параметр | Назначение |
| --- | --- |
| IP_MONITOR_SETTINGS_PATH | Путь к файлу монитора IP с секцией main и ключом ip_adress |
| IP_CHECK_URL | Основной ресурс определения внешнего IP, по умолчанию api.ipify.org |
| IP_CHECK_FALLBACK_URL | Дополнительный ресурс, по умолчанию https://api.2ip.io; вызывается после корректного ответа основного с несовпадающим IP |

## Питание Windows

| Параметр | Назначение |
| --- | --- |
| POWER_MODE | shutdown / sleep / hibernate; режим выбирается явно, неподдержанный сон не заменяется выключением |
| POWER_ENABLED | Разрешает работу модуля питания, включая вызов из 1С |
| POWER_BACKGROUND_ENABLED | Разрешает автоматическую фоновую проверку; false сохраняет возможность вызова API при POWER_ENABLED=true |
| POWER_DRY_RUN | true — только проверка без реального выключения |
| POWER_EXCLUDED_USER | Пользователь, не учитываемый при проверке бездействия. Пусто: WORKER_ACCOUNT в broker, пользователь API в inline |
| POWER_USER_IDLE_SECONDS | Порог бездействия остальных пользователей, секунды; 900 = 15 минут |
| POWER_CHECK_INTERVAL_SECONDS | Период фоновой проверки, секунды |
| POWER_GRACE_SECONDS | Пауза перед переходом питания, секунды |
| POWER_RESUME_COOLDOWN_SECONDS | Период защиты после обнаруженного возобновления работы, секунды |

Сохранённые переопределения API имеют приоритет над POWER_* по каждому полю. Бездействие клавиатуры/мыши не доказывает отсутствие длительного расчёта в 1С. Очередь API учитывается отдельно. Полный алгоритм и методы: [модуль питания](../project-guide/09-power-management.md).

## Демонстрационные параметры

| Параметр | Назначение |
| --- | --- |
| DEMO_1C_CALLBACK_ENABLED | Включает встроенный демонстрационный endpoint callback; в эксплуатации обычно не нужен |
| DEMO_MAIL_LOGIN / DEMO_MAIL_PASSWORD | Учётная запись встроенного почтового стенда |
| YAHOO_MAIL_URL | Адрес входа для старого почтового demo |
| YAHOO_MAIL_LOGIN / YAHOO_MAIL_PASSWORD | Учётные данные старого demo, не используются для СБИС |
| YAHOO_MAIL_RECIPIENT | Получатель старого почтового demo |

UN_LOGIN/UN_PASSWORD в локальной рабочей конфигурации разработчика — доступ к Windows-УН для администрирования. Они не являются API-настройками авторизации заданий; не раздавайте их как часть шаблона парка. NODE_TLS_REJECT_UNAUTHORIZED=0 не включайте: это отключает проверку TLS.

## Оркестратор имеет отдельную конфигурацию

Не добавляйте FLEET_* в env API в ожидании, что он станет оркестратором.

| Параметр controller.env | Назначение |
| --- | --- |
| FLEET_HOST / FLEET_PORT | Адрес и порт центрального HTTP-сервиса за HTTPS-прокси |
| FLEET_DATA_DIR | Постоянные база и пакеты центрального сервиса |
| FLEET_ADMIN_TOKEN | Секрет администратора центра, минимум 32 символа |
| FLEET_RELEASE_PUBLIC_KEY | Путь публичного ключа проверки подписанных релизов |
| FLEET_MAX_CONCURRENT | Общий максимум одновременных назначений обновления |

Агент на УН использует отдельный agent.config.json: central_url, node_id, un_id, token, api_url, project_path, env_file, worker_task_name, worker_task_path, backup_root, data_dir, release_public_key, poll_seconds. Его token индивидуален и отличается от API_KEY и FLEET_ADMIN_TOKEN. Полный пример — [агент](../../fleet/agent.config.example.json), процедуры — [оркестратор](../project-guide/11-fleet-updates.md).
