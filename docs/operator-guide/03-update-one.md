# Обновить одну УН до релиза из Git

Не выполняйте git pull поверх работающего API: он не обеспечивает согласованную остановку, резервную копию, установку зависимостей и откат. Git используется как источник **точного commit**, а обновление выполняется помощником.

1. На компьютере выпуска выполните git fetch и выберите проверенный SHA. Соберите ZIP как в [первой установке](01-install-one.md), прочитайте version из package.json выбранного commit и запишите SHA-256 ZIP.
2. Скопируйте ZIP и актуальный `docs/project-guide/tools/update-one-un.ps1` отдельно на УН, например в C:\Deploy. В ZIP package.json должен лежать прямо в корне, без папки repo-main.
3. Согласуйте окно, приостановите новые задания из 1С, дождитесь завершения очереди и callback. Пользователь worker должен быть залогинен. На время пилота выключите фоновые проверки питания через API, предварительно сохранив политику.
4. Проверьте действующие ProjectPath, EnvFile, TaskName, TaskPath, PORT и UN_ID. Исторический путь с другой УН не копируйте вслепую.
5. Выполните в повышенной PowerShell:

```powershell
& C:\Deploy\update-one-un.ps1 `
  -ProjectPath C:\script_factory `
  -EnvFile C:\script_factory\.env `
  -PackageZip C:\Deploy\release.zip `
  -ExpectedVersion '0.11.0' `
  -ExpectedSha256 'ВСТАВЬТЕ_SHA256_СОГЛАСОВАННОГО_АРХИВА' `
  -TaskName 'ScriptFactory-Test-UN' `
  -Port 33001 `
  -ConfirmNoNewJobs -ConfirmReplaceCode
```

Замените версию и контрольную сумму на фактические. Помощник сохраняет код, env, задачи и данные, останавливает процессы, устанавливает пакет и проверяет готовность. При неудаче пытается восстановить прежнюю установку. Не прерывайте его во время копирования. Для перехода на 0.11.0 предусмотрена миграция на две задачи; пользовательский сеанс нужен для итогового health.

6. Проверьте /health, ожидаемые UN_ID/version, [безопасный сценарий](06-first-script.md), скачивание результата и callback при необходимости. Проверьте Saby под тем же worker. После этого верните политику питания и приём заданий из 1С.

Полная процедура, ограничения и ручной откат: [обновление одной УН](../project-guide/04-update-one-un.md). Помощник накладывает файлы и не меняет Git HEAD на УН: после обновления фактическую версию определяют package.json и /health, а не старый локальный git log. Обновление ОС, Node, браузера и несовместимая миграция БД требуют отдельной процедуры.

Если агент уже установлен, одну УН можно выбрать в панели оркестратора и обновить тем же способом, что [десять УН](04-update-ten.md), с batch_size=1.
