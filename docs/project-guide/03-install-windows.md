# Установить систему на Windows-УН

## 1. Подготовить программы и пользователя

Нужны Windows, Node.js 24+ для всей машины, Яндекс Браузер, каталог проекта и его npm-зависимости. Для сценария СБИС дополнительно нужны Saby/СБИС Плагин, криптопровайдер и ЭЦП под тем Windows-пользователем, который запускает worker. Эти компоненты настраиваются средствами их поставщиков; система не устанавливает и не выпускает ЭЦП.

После установки Node.js закройте прежнюю PowerShell и откройте новую от администратора: уже открытая консоль не получает новый PATH автоматически. Перезагрузка всей УН ради этого обычно не нужна. Для автоматизированного продолжения в прежней консоли обновите окружение процесса:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')
node --version
npm.cmd --version
```

Проверьте вручную вход по нужной подписи под будущим worker-пользователем. ЭЦП другого пользователя Windows может быть недоступна worker. Для BROWSER_HEADLESS=false пользователь должен оставаться залогинен. На проверенной УН отключённый сеанс Robot (`Диск` в quser) мешал запуску Яндекса; перевод его на активную консоль устранил этот отказ. Поэтому одного факта входа в Windows недостаточно. SSH удобен для администрирования, но необязателен; возможен RDP.

Проверьте сеансы и пользователя задачи:

```powershell
quser
(Get-ScheduledTask -TaskName 'ScriptFactory-Test-UN').Principal |
  Select-Object UserId,LogonType,RunLevel
```

RDP-пользователь и пользователь worker могут различаться: вход администратора в свой сеанс не запускает Saby в сеансе Robot. Откройте Saby под worker-пользователем и подтвердите доступность нужной ЭЦП именно там. Установленный на диске Saby без процесса в нужном сеансе ещё не доказывает готовность входа или файлового диалога. При занятости RDP согласуйте доступ; не выходите из чужого Windows-сеанса. `tscon ID /dest:console` зависит от пользователя и прав: под другой учётной записью возможна ошибка 1326. Не публикуйте пароль в команде и не считайте передачу сеанса успешно выполненной без повторной проверки quser.

Входящие API-запросы должны доходить до адреса/порта УН; нужны Windows Firewall и, при наличии, проброс на маршрутизаторе. Сервис внутри УН не настраивает внешний NAT. Для ip-check нужен исходящий HTTPS к api.ipify.org и api.2ip.io и действующие настройки IP-монитора.

## 2. Положить проект в один известный каталог

Далее пример `C:\script_factory`. Рабочие XML храните в постоянной папке, например `C:\отчеты`, а не на рабочем столе, если он очищается регламентным скриптом. Каталог данных и архив также вынесите из очищаемых папок. Не накладывайте новый проект поверх неизвестной старой установки. Для существующей УН используйте [обновление](04-update-one-un.md).

Получите ZIP согласованного релиза от разработчика либо клонируйте Git и выберите конкретный commit. В корне должны лежать package.json, package-lock.json, src/server.js, windows/start-worker.ps1, windows/install-task.ps1 и windows/.env.example. ZIP из инструкции обновления имеет эти файлы прямо в корне; ZIP «Download source» GitHub обычно содержит дополнительную папку — сначала перенесите её содержимое в каталог проекта.

Откройте Windows PowerShell **от имени администратора**:

```powershell
$ProjectPath = 'C:\script_factory'
Set-Location $ProjectPath
node --version
npm.cmd --version
Copy-Item windows\.env.example .env
notepad .env
```

Copy-Item выполняется только при первой установке. При наличии .env не перезаписывайте его шаблоном.

## 3. Заполнить конфигурацию

| Переменная | Что задать |
| --- | --- |
| API_KEY | Собственный ключ для 1С; не оставлять dev-secret/replace |
| UN_ID | Уникальный постоянный идентификатор УН |
| WEB_LOGIN / WEB_PASSWORD | Вход в веб-интерфейс; отдельный от ключа API |
| HOST / PORT | `0.0.0.0` и `33001`, если доступ нужен с других компьютеров |
| DATA_DIR | Например `C:/ScriptFactoryData`; база и артефакты переживают обновления |
| FILESYSTEM_ALLOWED_ROOTS | Корни через `;`, включая каталоги рабочих XML и архивов |
| PUPPETEER_EXECUTABLE_PATH | Реальный полный путь к browser.exe |
| BROWSER_PRODUCT | Метка `yandex`; браузер выбирает реальный executable, одна эта метка путь не переключает |
| BROWSER_HEADLESS | `false` для видимой отладки СБИС |
| MAX_PARALLEL_JOBS | Для одного кабинета/сеанса СБИС — `1` |
| CALLBACK_AUTH_TOKEN | Токен авторизации callback; текущий Windows preflight требует его заполнить |
| CALLBACK_ALLOWED_ORIGINS | Origin 1С по HTTP или HTTPS (0.9.2+), например `http://1c-test.local:8080`, без пути обработчика; несколько адресов разделяются запятыми |
| NOVNC_ENABLED | Для Windows/RDP обычно `false` |

Для JSON-сценария СБИС 3.5.0 заранее создайте `C:/Отчеты_с_ошибками` (или свой `error_dir`) и разрешите доступ к нему пользователю worker. После изменения `.env` перезапустите worker при пустой очереди.

Пример только несекретных строк:

```dotenv
HOST=0.0.0.0
PORT=33001
DATA_DIR=C:/ScriptFactoryData
FILESYSTEM_ALLOWED_ROOTS=C:/отчеты;C:/Отчеты_загруженные;C:/Отчеты_с_ошибками;C:/ScriptFactoryData
PUPPETEER_EXECUTABLE_PATH=C:/Program Files/Yandex/YandexBrowser/Application/browser.exe
BROWSER_PRODUCT=yandex
BROWSER_HEADLESS=false
MAX_PARALLEL_JOBS=1
NOVNC_ENABLED=false
```

Заполните API_KEY, WEB_PASSWORD, CALLBACK_AUTH_TOKEN своими значениями. Шаблон windows/.env.example задаёт параллельность 3 — для СБИС измените её на 1. Параметр -Port установщика сам не меняет PORT в .env: оба значения должны совпадать.

Создайте каталоги и предоставьте worker-пользователю чтение программы, доступ к .env, запись в DATA_DIR и рабочие корни. Не распечатывайте весь .env в журнал или переписку.

## 4. Настроить IP-монитор для СБИС

Сценарий СБИС вызывает system_ip_check. По умолчанию читается `C:\_external ip monitor\settings.ini`:

```ini
[main]
ip_adress=ФАКТИЧЕСКИЙ_ВНЕШНИЙ_IP
```

Имя ключа именно `ip_adress`. Здесь должно быть действующее значение, а не placeholder. Не заменяйте работающие настройки монитора для обхода проверки. Если используется другой файл, задайте IP_MONITOR_SETTINGS_PATH в .env. Допустимы IPv4 и IPv6. Health не обращается к ipify, поэтому ready=true не доказывает успех ip-check.

## 5. Установить зависимости и задачу

```powershell
$env:PUPPETEER_SKIP_DOWNLOAD = 'true'
npm.cmd ci --omit=dev
if ($LASTEXITCODE -ne 0) { throw 'Не установлены зависимости' }

& .\windows\install-task.ps1 `
  -ProjectPath $ProjectPath `
  -TaskName 'ScriptFactory-Test-UN' `
  -RunAsUser 'ИМЯ_ПК\Robot' `
  -Port 33001 `
  -SkipDependencyInstall
```

Замените пользователя существующим worker-пользователем. Используем npm.cmd явно: Windows может выбрать npm.ps1, блокируемый ExecutionPolicy. -SkipDependencyInstall предотвращает повторный вызов npm внутри старого установщика.

Установщик проверяет конфигурацию, регистрирует интерактивную Scheduled Task с запуском при входе указанного пользователя, запускает скрытый контролирующий процесс и пытается создать входящее правило Firewall. Пользователь должен быть залогинен. Не запускайте две задачи на один порт/один DATA_DIR.

При блокировке выполнения .ps1 запустите отдельное окно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass
```

Это настройка одного процесса PowerShell, а не постоянное отключение политики на всей машине.

## 6. Проверить установленную УН

```powershell
$h = Invoke-RestMethod http://127.0.0.1:33001/health -TimeoutSec 10
$h | Select-Object status,ready,version,release_date,un_id
Get-ScheduledTask -TaskName 'ScriptFactory-Test-UN' | Select-Object TaskName,State
```

Требуются ready=true, нужный UN_ID, ожидаемая версия и успешные проверки базы, файловой системы и браузера. После этого проверьте из компьютера 1С тот же адрес, затем [безопасное задание и IP](06-api-1c.md).

В браузере доступны `/`, `/docs`, `/queue`. Вход в веб-интерфейс использует WEB_LOGIN/WEB_PASSWORD, API — X-API-Key.

Если не запустилось: выполните `windows/start-worker.ps1` вручную под worker-пользователем после остановки его задачи и посмотрите ошибку; проверьте node в PATH, путь браузера, .env и права каталогов. Перед возвратом Scheduled Task завершите ручной процесс, чтобы не оставить два worker.

## 7. Если Яндекс запускается, но аварийно закрывается

На Яндексе 24.1.3.869 воспроизведён выход `0xC0000005` при открытии СБИС со стандартными аргументами Puppeteer. В API 0.6.19 для json-workflow добавлен `browser_launch.params.ignore_default_args=true`: минимальный запуск сохраняет настроенный браузер и признак автоматизации. В сценарии СБИС 2.0.2 он управляется параметром `browser_ignore_default_args` (по умолчанию true). Это параметр JSON, не новая строка `.env`; он не переключает систему на Chrome.

Режим не применяется автоматически к необёрнутой записи Recorder. Для такой записи сначала используйте [преобразование в workflow](01-scripts.md). После исправления запуска отдельно проверяйте вход, полный ИНН, файловый диалог и конкретный отчёт. `ready=true` и открытый браузер не доказывают прохождение этих этапов.


## Проверенная чистая установка 19.10.2026

На новой Windows Server 2022 (build 20348) первоначально не было Node.js, проекта, зависимостей и задачи API. Выполнена установка официального Node.js 24 LTS x64 с проверкой SHA-256 и Authenticode, распаковка релиза в C:\script_factory, создание .env из windows/.env.example, отдельного DATA_DIR и архива, npm.cmd ci и штатная install-task.ps1 с -SkipDependencyInstall. Задача запущена под уже вошедшим пользователем с доступным СБИС; имя Robot не обязательно. Проверены ready=true, уникальный UN_ID, режим Yandex и параллельность 1. Вход и организация проверены preflight-сценарием; API доступен с другой УН внутренней сети. Конкретные реквизиты, пути файлов и ключи этой установки хранятся вне Git.

Не считайте предупреждение npm ошибкой без проверки кода завершения. При интерактивном запуске используйте команды раздела 5 без перенаправления stderr. Если автоматизируете журналирование в Windows PowerShell 5.1, сочетание `$ErrorActionPreference='Stop'` и `2>&1` может превратить обычный native stderr в исключение. Сохраните прежний ErrorActionPreference, временно используйте Continue для native-команды, сохраните LASTEXITCODE сразу после npm.cmd и восстановите прежний режим; установка успешна только при коде 0. Предупреждения о безопасности или политике install scripts рассматриваются отдельно, не подавляются как доказательство успеха.

## Скрытый запуск и восстановление API (0.9.1+)

Штатная задача запускает `start-worker.ps1 -RestartOnExit` с `-WindowStyle Hidden`. Консоли PowerShell и Node скрыты; Яндекс остаётся доступен в том же пользовательском сеансе с его ЭЦП. При завершении Node контролирующий процесс ждёт 10 секунд и запускает API заново без ограничения числа попыток. Если завершился сам контролирующий процесс, Планировщик делает до трёх повторов с интервалом в минуту. Выход пользователя из Windows и выключение УН не являются авариями для автоматического восстановления: после включения нужен вход worker-пользователя.

Контроль проверяет завершение процесса, а не время ответа HTTP. Занятый, медленный или временно `ready=false` API не перезапускается. Если прежний процесс этой конфигурации ещё существует, второй не запускается; mutex исключает два штатных контролирующих процесса. Не запускайте вручную `npm start` параллельно задаче и не используйте разные `.env` с одним DATA_DIR.

Журналы находятся в `DATA_DIR\worker-logs`: `supervisor.log` содержит PID, сеанс, время запуска и код завершения; `worker-…-out.log` / `worker-…-err.log` — вывод API. Сохраняются последние 20 запусков, журнал контроллера ротируется при размере больше 1 МиБ. Журналы API могут содержать рабочие данные: не публикуйте их в Git.

Процесс API привязан к контроллеру через [Windows Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) с `KILL_ON_JOB_CLOSE`: при остановке контроллера Windows завершает его дерево процессов, включая запущенные им браузеры. Это не затрагивает программы, которые пользователь открыл самостоятельно.

Для обслуживания остановите **задачу Планировщика целиком**, а не только Node: иначе Node запустится снова. Сначала приостановите новые задания из 1С и дождитесь пустой очереди. Убедитесь, что исчез слушатель порта; при оставшемся Node завершайте только проверенный PID этой установки, как делает помощник обновления. После обслуживания запустите задачу. Ручной `start-worker.ps1` без `-RestartOnExit` сохраняет обычный запуск в консоли для диагностики.

Проверка восстановления допустима только при пустой очереди: запишите PID и SessionId слушателя, завершите именно этот Node, дождитесь нового PID и `ready=true`, проверьте прежний SessionId и безопасное задание. Не имитируйте сбой во время загрузки, подписи, отправки отчётов или передачи результата.

В 0.9.2+ Windows-задача требует файл конфигурации (`node --env-file=...`). Если `.env` временно отсутствует при его замене, Node завершится, а контроллер повторит запуск через 10 секунд. Запуск без файла через `--env-file-if-exists` больше не используется: это исключает переход к значениям по умолчанию вместо конфигурации УН.


## Saby в сеансе пользователя API

Для входа по ЭЦП приложение Saby должно быть доступно в том же пользовательском сеансе Windows, где работает API. Запущенного Saby под другой учётной записью может быть недостаточно. Наличие установленного приложения и службы Saby Center само по себе не подтверждает готовность входа.

После установки Saby выполните из повышенного PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\script_factory\windows\install-saby-task.ps1 -ProjectPath C:\script_factory -ApiTaskName ScriptFactory-Test-UN
```

Скрипт берёт учётную запись из существующей задачи API и создаёт отдельную задачу `ScriptFactory-Saby`. Параметр `-RunAsUser` допускается только для той же Windows-учётной записи. Для нестандартной установки задайте `-ExecutablePath`, для общего каталога журнала — `-LogDirectory`. Основная задача API и `.env` не изменяются.

Задача запускается сразу и при последующих входах этого пользователя в Windows. Скрытый PowerShell проверяет процессы `saby.exe` по полному пути и своему SessionId; работа приложения под другим пользователем не считается готовностью. При отсутствии процесса запускает Saby, повторная проверка — каждые 5 секунд; после запуска или ошибки — пауза 15 секунд. Повторный запуск задачи не создаёт второй supervisor. Процессы Saby других пользователей не завершаются.

По умолчанию журнал находится в `%LOCALAPPDATA%\ScriptFactory\logs\saby-supervisor.log` пользователя API; после 1 МБ сохраняется предыдущий файл. Для отключения автоматического запуска остановите и отключите задачу `ScriptFactory-Saby`. После перезагрузки требуется вход пользователя API в Windows: эта задача использует интерактивный сеанс и не заменяет настройку входа в систему. Проверка процесса не подтверждает доступность сертификатов или готовность всех экранов СБИС; это проверяется входом в браузере.
