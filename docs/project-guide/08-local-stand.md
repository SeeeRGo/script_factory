# Проверить полный цикл на локальном стенде

Стенд выполняет [полный JSON СБИС](../../demo/sbis-report-full.json) через настоящий API и браузер на учебных страницах. ЭЦП, импорт, проверка и отправка имитируются. Он не открывает СБИС, не подписывает документы и не отправляет данные в ведомства. Учебные XML не являются отчётами.

## Запуск

Из установленного проекта с Node.js 24 и установленными зависимостями:

```powershell
Set-Location C:\script_factory
npm.cmd run demo:sbis:local-stand -- --headed
```

На Windows запускайте из активного интерактивного сеанса пользователя, которому доступен браузер. Путь берётся из `PUPPETEER_EXECUTABLE_PATH` в `.env`; если он недоступен, стенд ищет установленный Яндекс в LOCALAPPDATA / Program Files, как Windows-launcher проекта. Найденный путь задаётся только изолированному процессу. В Linux при отсутствии пути используется `/usr/bin/chromium`; без `--headed` браузер запускается без окна.

Стенд создаёт отдельный API на случайном порту 127.0.0.1, отдельную базу, случайный ключ и локальный callback. Основные `.env`, база, задача запуска и очередь УН не меняются. Дополнительный браузер временно использует ресурсы машины; запускайте в свободное время. Изолированный API закрывается после проверки.

## Ожидаемые результаты

| Случай | Результат | Что проверяется |
| --- | --- | --- |
| success | success / sent | Все три ведомства, три имитации отправки, архив трёх XML и трёх протоколов |
| license | failed / license_required | REPORTING_LICENSE_REQUIRED, нет отправки и архива |
| unknown | failed / requires_reconciliation | Одна имитация отправки без подтверждения, нет повторной отправки и архива |

Каждый случай сравнивает скачанный последний `result-N.json` с `job.result.Rezult_1`, затем с полученным callback. Успешный запуск выводит `scenarios_passed: 3` и путь к `work/sbis-local-XXXX/proof.json`. Рядом остаются учебные результаты, callback и технический журнал; каталог `work` исключён из Git. При ошибке команда завершается с ненулевым кодом; изучите журнал в созданном каталоге.

Это проверка исполнителя и логики сценария. Она не доказывает пригодность реальных UI-привязок, выбор реальной ЭЦП, подписание, доставку отчёта или работу обработчика в настоящей 1С. Реальные подтверждения и ограничения перечислены в [документе 07](07-verification.md).
