# Индивидуальные параметры СБИС и правила ui

Сценарий: [demo/sbis-report-full.json](../../demo/sbis-report-full.json), версия 2.0.1, формат json-workflow. Сервис 0.6.17 добавил поля API, но не менял эти параметры.

## Основные значения

| Параметр | Тип / по умолчанию | Значение |
| --- | --- | --- |
| inn | Строка / null | ИНН организации, 10 или 12 цифр, обязателен |
| mode | Строка / validate_only | preflight: вход/переходы/сверка без импорта; validate_only: импорт/проверка без отправки; send: допускает отправку |
| submit_enabled | Boolean / false | Отправка разрешена только вместе с mode=send, успешной проверкой и настроенными шагами отправки |
| root_dir | Строка / null | Каталог исходных XML на УН, в разрешённых корнях |
| loaded_dir | Строка / null | Существующий каталог архивирования подтверждённых отправок; не используется для перемещения в validate_only |
| allow_multiple | Boolean / true | Несколько самостоятельных отчётов одного ведомства; не означает поддержку частей одного комплекта |
| authority_prefixes | Массив | Один–три объекта {authority,prefixes,ui?}; ведомство нельзя повторять |
| authority / prefixes | Код / массив | Используются только при authority_prefixes=null; одного изменения этих полей недостаточно при заданном массиве |

Для каждого префикса выбирается один последний изменённый XML. Одинаковый выбранный путь внутри ведомства исключается повторно; выбор одного пути для двух ведомств запрещён. Префиксы регистрозависимы. files_list не обходит подкаталоги. Отсутствие файла останавливает и preflight: этот режим выбирает файлы, но не импортирует их.

## Соответствие вашей таблице

| Контролирующий орган | Код | Префиксы |
| --- | --- | --- |
| ФНС | FNS | NO_BOUPR, NO_NDFL3 |
| СФР | SFR | POVD |

Это два объекта, а не три; два префикса ФНС объединяются. Росстат не добавляется без соответствующих отчётов. [Пример входных данных](examples/sbis-input.example.json) — только context, не готовый API-запрос. Префиксы не подтверждают валидность XML или готовность экранных привязок.

## Общий ui и ui ведомства

context.ui — общие адреса, селекторы, шаги и проверки экранов. authority_prefixes[].ui переопределяет отдельные поля для ведомства. Итог вычисляется как `{...context.ui, ...plan.ui}`: при совпадении побеждает настройка ведомства; массив/вложенный объект заменяется целиком.

В ui находятся, например, organization_steps, organization_selector, upload_steps, validate_steps, validation_status_selector, protocol_selector, validation_success_text, validation_failure_text, reopen_steps, submit_steps и sent_status_selector. Это технический профиль экрана, а не название госоргана или префикс XML.

Важны два разных уровня замены:

1. context задания поверхностно заменяет context сценария. Новый authority_prefixes заменяет весь массив, включая вложенные ui старых элементов.
2. Уже внутри сценария каждый plan.ui поверхностно дополняет общие context.ui.

В текущем полном JSON профиль панели ошибок ФНС находится именно в элементе authority_prefixes. При подстановке массива из таблицы его нужно сохранить. Нельзя обещать рабочий запуск массива без ui: общие validation_status_selector/protocol_selector пока null, СФР/Росстат требуют проверенных профилей импорта и проверки.

Предпочтительно хранить ui в шаблоне, а в 1С менять бизнес-поля. Пока отдельного автоматического слияния нового массива с профилями шаблона нет: 1С должна перенести нужные ui при формировании массива либо заранее подготовить полный JSON-профиль с подходящими префиксами.

## Дополнительные настройки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| certificate_inn | null | ИНН владельца ЭЦП; при null используется inn |
| certificate_selection_required | false | true требует явного выбора подходящей ЭЦП; неподтверждённый автоматический вход отклоняется |
| skip_security_setup | true | Пропуск необязательной настройки логина/пароля; первичная регистрация кабинета не выполняется |
| upload_directory_steps | [] | Шаги перехода в нужную подпапку диалога; root_dir сам его не переключает |
| validation_timeout_ms | 300000 | Ожидание проверки, 1–900000 мс; дополнительно ограничено заданием |
| submit_timeout_ms | 300000 | Ожидание отправки, 1–900000 мс; дополнительно ограничено заданием |
| login_url / report_url / authenticated_url | Адреса СБИС/Saby | Вход, отчётность, подтверждённый кабинет; обычно оставить шаблонные |

Не передавайте служебные submission_started, plans, reports и промежуточные результаты как индивидуальные параметры. Результат для 1С — job.result.Rezult_1; текст проверки — отдельный артефакт. Сохранённая панель ошибок не является официальной квитанцией ведомства.

## Что пока нельзя считать готовым

Обход ФНС/СФР/Росстат, выбор раздела и сверка организации проверены. Реальный импорт и сохранение текста ошибок проверены для тестовой НДС ФНС. NO_BOUPR, NO_NDFL3 и POVD ещё требуют соответствующих XML и проверок экранов. Успешная проверка корректного отчёта и реальная отправка не подтверждены.

Если два XML открывают одну карточку, возвращается REPORT_BUNDLE_REQUIRED: связанные разделы отчёта пока не обрабатываются как комплект. После отправки без подтверждённого исхода требуется сверка с сайтом, а не автоматический повтор.
