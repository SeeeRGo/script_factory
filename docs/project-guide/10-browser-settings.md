# Настройки браузера и исполнителя — API 0.9.15+

Общая конфигурация действует в `json-workflow` и нативном `puppeteer-replay`. Она задаёт запуск браузера, профиль, расширения, ожидания, интерфейс, прокси, диалоги и скачивание. Логика сайта по-прежнему остаётся в шагах JSON. Нативные окна Windows и программы КриптоПро/Saby не являются JavaScript-диалогами страницы.

## Где задавать настройки

Приоритет от меньшего к большему:

1. Значения по умолчанию и прежние переменные `.env` (`PUPPETEER_EXECUTABLE_PATH`, `BROWSER_HEADLESS`, `BROWSER_WINDOW_WIDTH/HEIGHT`, `BROWSER_STEP_DELAY_MS`, `BROWSER_HOLD_OPEN_MS`, `BROWSER_CAPTCHA_WAIT_MS`).
2. `BROWSER_OPTIONS_JSON` в `.env` — общие настройки УН.
3. `browser` на верхнем уровне сценария — настройки конкретного сценария.
4. `parameters.context.browser` запроса — настройки задания.
5. Поля `browser_launch.params` — настройки конкретного запуска; это последний уровень только для `json-workflow`.

Объекты на уровнях сливаются по именам полей. Массивы и значения полей-объектов (например, `extra_http_headers`) заменяются целиком. Локальный вызов исполнителя из Node.js также поддерживает прежние аргументы; HTTP-клиенту они не нужны. Неизвестные имена полей возвращают `INVALID_BROWSER_OPTIONS`, а не игнорируются. Настройки browser в сценарии и контексте задаются готовыми значениями; `browser_launch.params` дополнительно поддерживает обычные шаблоны `{{variable}}`.

Пример `.env` (каждая переменная занимает одну строку):

```dotenv
BROWSER_OPTIONS_JSON='{"launch_timeout_ms":90000,"protocol_timeout_ms":240000,"user_data_dir":"C:/ScriptFactoryBrowser/robot","enable_extensions":true,"window_width":1600,"window_height":1000,"step_delay_ms":250}'
WORKFLOW_LIMITS_JSON='{"max_steps":30000,"max_iterations":3000,"compute_timeout_ms":3000}'
```

После изменения `.env` нужен перезапуск worker. В вызовах API можно менять настройки через JSON без перезапуска. Общий лимит `parameters.timeout_ms` продолжает действовать.

Пример запроса из 1С (поле script здесь сокращено):

```json
{
  "parameters": {
    "timeout_ms":1800000,
    "context": {
      "browser": {"step_delay_ms":0,"dialog_action":"dismiss"}
    }
  },
  "script": {
    "format":"json-workflow",
    "browser": {"headless":false,"launch_timeout_ms":90000},
    "steps": [{"action":"browser_launch","timeout_ms":95000}]
  }
}
```

## Полный каталог browser

Все времена — миллисекунды. Для тайм-аутов требуется целое число 1..2147483647; для задержек и ручного ожидания CAPTCHA допустим 0 (выключить). Большие значения не обрезаются молча.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `executable_path` | null | Путь к Chrome/Яндексу. При null используется штатный поиск браузера. Задание может выбирать только путь, разрешённый в конфигурации УН |
| `headless` | true | Фоновый режим; false открывает окно в сеансе worker |
| `launch_timeout_ms` | 30000 | Время ожидания запуска браузера |
| `protocol_timeout_ms` | 180000 | Время ответа на служебную команду Puppeteer/CDP |
| `default_timeout_ms` | 30000 | Базовое ожидание страницы; также browser_steps/browser_wait, если в них нет явного времени |
| `navigation_timeout_ms` | 30000 | Базовое ожидание навигации страницы и открытия локального файла |
| `window_width`, `window_height` | 1400, 860 | Размер окна, положительные целые числа |
| `viewport` | `"auto"` | auto: размеры из настроек для headless, без эмуляции для видимого окна. null: без эмуляции. Объект: viewport Puppeteer, минимум width/height |
| `user_data_dir` | null | Корневой каталог постоянного профиля. null создаёт временный профиль для задания |
| `profile_directory` | null | Имя профиля внутри user_data_dir, например Default или Profile 1; не полный путь |
| `enable_extensions` | false | Разрешить установленные расширения браузера |
| `extensions` | [] | Пути к каталогам распакованных расширений; их загрузка также включает enable_extensions |
| `args` | см. ниже | Массив аргументов запуска браузера; заменяет исходный массив целиком |
| `ignore_default_args` | false | false: обычные аргументы Puppeteer; true: минимальный запуск; массив: исключить перечисленные аргументы Puppeteer |
| `proxy_server` | null | Адрес прокси, например http://proxy.local:3128 |
| `proxy_bypass_list` | null | Список исключений Chromium, например localhost;127.0.0.1 |
| `proxy_username`, `proxy_password` | null | Учётные данные для HTTP-аутентификации браузера, включая прокси. Предпочтительно хранить в конфигурации УН, не в общем сценарии |
| `accept_insecure_certs` | false | Разрешать недоверенные HTTPS-сертификаты |
| `user_agent` | null | Подмена User-Agent |
| `locale` | null | Язык запуска и заголовок Accept-Language, например ru-RU |
| `timezone_id` | null | Часовой пояс страницы, например Europe/Samara |
| `extra_http_headers` | {} | Дополнительные HTTP-заголовки, объект строк. Явный Accept-Language здесь имеет приоритет над locale |
| `slow_mo_ms` | 0 | Задержка служебных операций Puppeteer |
| `step_delay_ms` | 0 | Пауза после каждого браузерного действия Recorder, включая последнее; действует в обоих форматах |
| `hold_open_ms` | 0 | Оставить окно после успешного выполнения сценария; входит в общий лимит задания |
| `captcha_wait_ms` | 0 | Ожидание ручного подтверждения обнаруженной CAPTCHA Яндекса; требуется видимый браузер |
| `captcha_poll_ms` | 500 | Интервал проверки окончания CAPTCHA. Другие CAPTCHA описываются условиями конкретного сценария |
| `download_dir` | null | Каталог скачивания. При его указании default-политика автоматически становится allow |
| `download_behavior` | default | default, allow, deny, allowAndName. allowAndName сохраняет файлы с идентификаторами браузера вместо исходного имени |
| `dialog_action` | dismiss | Ответ на alert/confirm/prompt: dismiss, accept или ignore (оставить без автоматического ответа) |
| `dialog_prompt_text` | пустая строка | Текст ответа при автоматическом принятии prompt |
| `permissions` | [] | Массив `{origin,permissions}`, например `[{"origin":"https://example.org","permissions":["geolocation"]}]` |

Исходный массив args: `--no-sandbox`, `--disable-setuid-sandbox`, `--disable-dev-shm-usage`. Размер окна и явно заданные профиль/прокси/расширения добавляются отдельно. Пути профиля, каталог скачивания и пути расширений задаются именованными полями; передача соответствующих флагов через args запрещена, чтобы не обходить проверку разрешённых каталогов. Параметры remote-debugging через args также запрещены: соединением управляет API. Флаги запуска внешних процессов Chromium (например renderer-cmd-prefix) запрещены.

Каталоги профиля, расширений и скачивания должны входить в `FILESYSTEM_ALLOWED_ROOTS`. Каталог расширения должен существовать. Если профиль или каталог скачивания отсутствует, может быть создан один дочерний каталог внутри существующего разрешённого родителя. Произвольная цепочка промежуточных каталогов автоматически не создаётся. У пользователя worker должны быть необходимые права.

Постоянный профиль сохраняет cookies, локальное хранилище, настройки и установленные расширения между заданиями. Одновременно открыть один профиль несколькими браузерами нельзя: для СБИС используйте MAX_PARALLEL_JOBS=1 либо разные каталоги профилей. Расширения зависят от совместимости версии браузера; наличие флага enable_extensions не устанавливает КриптоПро или Saby. Для распакованных расширений задаются каталоги, а не файлы .crx.

## Пример постоянного профиля на Windows

1. Создайте `C:\ScriptFactoryBrowser` и `C:\ScriptFactoryDownloads`, предоставьте robot права записи.
2. Добавьте оба каталога в FILESYSTEM_ALLOWED_ROOTS через `;`, сохранив существующие корни.
3. Укажите user_data_dir=`C:/ScriptFactoryBrowser/robot`, download_dir=`C:/ScriptFactoryDownloads/reports`, enable_extensions=true.
4. Перезапустите worker. Настройте необходимые расширения именно в выбранном профиле.
5. При заданиях с загрузкой дождитесь завершения скачивания до окончания сценария: закрытие браузера может прервать незавершённый файл.

Профиль обычного вручную открытого браузера robot сам по себе не выбирается: решает user_data_dir. API продолжает работать под пользователем задачи планировщика.

## Как сочетаются тайм-ауты

Явный timeout действия Recorder имеет приоритет над timeout записи/`browser_steps.params.timeout_ms`. Явные параметры операции также имеют приоритет над базовым default_timeout_ms браузера. navigation_timeout_ms — стандарт страницы, а не замена явного timeout Recorder. Сценарий СБИС дополнительно задаёт browser_step_timeout_ms и внешний запас 5 секунд: настройка browser.default_timeout_ms не отменяет это явное значение.

Внешний steps[].timeout_ms, тайм-ауты составных шагов/циклов и общий parameters.timeout_ms продолжают ограничивать выполнение. Они не обнуляются из-за изменения браузерных настроек. Значение 0 не означает бесконечное ожидание операции.

В СБИС params.ignore_default_args задаётся параметром `context.browser_ignore_default_args` и имеет приоритет над общей настройкой browser.ignore_default_args.

## Настраиваемые лимиты json-workflow

УН: WORKFLOW_LIMITS_JSON. Сценарий: верхнеуровневый `limits`, который переопределяет `.env` по отдельным полям. Это ограничения исполнителя json-workflow, а не нативной записи Recorder.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `max_steps` | 10000 | Число реально выполненных шагов, включая циклы, подпрограммы и обработчики |
| `max_iterations` | 1000 | Число элементов одного for_each |
| `max_depth` | 25 | Глубина вложенности шагов и вызовов |
| `compute_timeout_ms` | 1000 | Время вычисления одного compute, положительное целое в диапазоне таймера Node.js |
| `max_expression_chars` | 100000 | Длина выражения compute в символах |
| `max_context_bytes` | 16777216 | Размер JSON-контекста, передаваемого в вычислительный worker, в байтах UTF-8 |
| `max_result_bytes` | 16777216 | Размер JSON-результата вычисления в байтах UTF-8 |
| `compute_memory_mb` | 64 | Память вычислительного worker, минимум 16 МБ |

Пример: `"limits":{"max_steps":30000,"max_iterations":3000,"compute_timeout_ms":5000}`. Нулевые, неизвестные и некорректные значения отклоняются. Изменение лимитов не даёт compute доступа к ОС, Node.js, файловой системе или асинхронному коду.

## Проверка и границы

В /health отображаются эффективные общие настройки пути браузера, headless и задержки. Некорректная конфигурация browser возвращает ready=false с причиной в checks.browser. Настройки конкретного задания могут переопределять общие, поэтому их нужно учитывать отдельно. Значения proxy_password и чувствительные заголовки редактируются в журнале запуска, однако содержимое самого POST-запроса сохраняется как часть задания — секреты лучше держать в .env.

На локальном Chromium проверены: постоянный профиль между двумя заданиями/форматами, распакованное учебное расширение, диалоги, скачивание, HTTP-аутентификация, размеры viewport, User-Agent, язык/заголовки, часовой пояс, разрешения страницы, приоритет параметров и ограничения путей. Реальный КриптоПро/Saby на Windows и корпоративный прокси требуют отдельной проверки на УН; установка и сертификаты сторонних продуктов этой настройкой не выполняются.


Для выбора другого исполняемого файла из JSON добавьте его полный путь в `.env`: `BROWSER_EXECUTABLE_ALLOWLIST='["C:/Program Files/Google/Chrome/Application/chrome.exe"]'`. Браузер, указанный через PUPPETEER_EXECUTABLE_PATH или BROWSER_OPTIONS_JSON на самой УН, уже разрешён. Список задаётся администратором и не переопределяется самим заданием; параметры browser не добавляют операцию произвольного запуска команд ОС.


Для launch_timeout_ms=90000 укажите наружный timeout_ms шага browser_launch больше 90000 (например 95000) либо увеличьте script.default_step_timeout_ms. Иначе наружный лимит шага может остановить запуск раньше внутреннего. Явно заданный executable_path больше не подменяется другим найденным браузером при ошибке: API сообщает, что выбранный файл недоступен. Автопоиск используется при отсутствии заданного пути.


Windows start-worker.ps1 и preflight.ps1 учитывают executable_path из BROWSER_OPTIONS_JSON. При отсутствии явного пути выполняется поиск Яндекса, затем Chrome. После изменения .env перезапустите задачу планировщика целиком, чтобы перечитать конфигурацию контролирующего процесса. Полный запуск Windows-скриптов с новой конфигурацией на реальной УН пока не проверен.


Минимальный режим ignore_default_args=true отдельно передаёт проверенный путь постоянного профиля: это нужно, поскольку Puppeteer пропускает стандартные аргументы. Сохранение профиля и загрузка учебного расширения проверены также в этом режиме, используемом СБИС. Явный Recorder-шаг setViewport может изменить размер страницы после запуска; это настройка самого сценария и она имеет приоритет над начальным viewport.
