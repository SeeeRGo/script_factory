## Что нужно для завершения рабочих профилей

Подходящие тестовые XML каждого типа на УН, доступ к нужной организации/ЭЦП и последовательный проход до результата проверки. Для профилей успеха и отправки отдельно нужны соответствующие экраны и разрешённый тестовый процесс. Нельзя подставлять условные селекторы из учебного примера в рабочий профиль.

## Рабочие отправки 13.10.2026

После отдельного подтверждения финансового действия «В долг» выполнены реальные подпись и отправка подготовленных РСВ ФНС и ЕФС-1 СФР. Отдельный JSON-сценарий без отправки повторно открыл обе карточки, сверил ИНН и подтвердил статус «Отчет сдан». Рабочие XML и протоколы проверки архивированы внутри разрешённого work; оригиналы на рабочем столе сохранены. Создан успешный общий результат для API/1С с JSON-артефактом и снимками. Файлы квитанций отдельно не выгружались.

Диагностические прогоны выявили позднюю стартовую навигацию Яндекса, групповую дату в журнале и несовпадение короткого ожидаемого статуса с полным фактическим текстом. Общий JSON 2.0.3 обновлён по результатам: начальная навигация до чтения DOM, два подтверждённых статуса, повторная проверка карточки после отправки, отдельное разрешение и точная сумма для лицензионного продолжения, предварительная проверка архива. Если условие if расположено неправильно или разрешилось в строку, API 0.6.20 отклоняет его вместо молчаливого пропуска ветки.

Реальные отчёты после подтверждения отправки для тестирования не отправлялись повторно. Новые ветви лицензии проверяются на учебных страницах. Настоящий XML Росстата, комплекты связанных XML, холодный запуск Windows и обработчик внутри реальной 1С остаются непроверенными.

Независимая проверка финансовой ветки выявила и устранила два риска: позднее изменение суммы перед нажатием «В долг» и противоречащий отправленный статус рядом с «Отчет создан». Сценарий сверяет цену, ИНН, ключ и неотправленный статус непосредственно перед нативным кликом и на его событиях; при противоречии сохраняет необходимость сверки. Отрицательные браузерные проверки охватывают изменение цены на pointerdown и одновременно видимые Created/«Отчет сдан». Реальные отчеты для этих проверок повторно не отправляются.

Проверки версии 0.6.20: полный прогон `npm test` — 127/127; после устранения вложенного браузерного `eval` повторно проверены все шесть финансовых случаев — 6/6. Изолированный API-стенд на Linux — 3/3 сценария, с вымышленными XML и callback. Это не заменяет проверку настоящего отчета Росстата и получение отдельных файлов квитанций ведомств.

На проверенной УН обновление до 0.6.20 выполнено штатным `update-one-un.ps1` при пустой очереди, с резервной копией и без смены зависимостей.
