# Ответы на вопросы по текущему этапу

Дата: 14.10.2026. Ответы относятся к API 0.6.21 и полному сценарию СБИС 3.0.0.

## 1. Разрешённые каталоги в .env: рабочий стол и сетевая папка

На Windows каталоги в `FILESYSTEM_ALLOWED_ROOTS` разделяются точкой с запятой. Например:

```dotenv
FILESYSTEM_ALLOWED_ROOTS=./work;./data;C:/Users/lawyer/Desktop/Отчеты;\\fileserver\Reports
```

Существующие разрешённые каталоги сохраните, новые добавьте к ним. Разрешение распространяется и на вложенные папки. `fileserver` — пример имени файлового сервера, замените его своим.

Для рабочего стола параметры задания будут такими:

```json
{
  "root_dir": "C:/Users/lawyer/Desktop/Отчеты",
  "loaded_dir": "C:/Users/lawyer/Desktop/Отчеты/Загруженные"
}
```

Для сетевой папки:

```json
{
  "root_dir": "\\\\fileserver\\Reports",
  "loaded_dir": "\\\\fileserver\\Reports\\Загруженные"
}
```

Обе папки должны существовать. Пользователь, под которым работает worker — на проверенной УН это Robot, — должен иметь необходимые права: чтение исходных файлов, запись в архив и удаление исходного файла при архивировании. Проверяйте доступ именно из сеанса этого пользователя. После изменения `.env` перезапустите worker при пустой очереди.

Ограничение сценария: автоматический переход в файловом диалоге СБИС настроен для диска `C:`. Для сетевого пути или другого диска дополнительно нужны шаги `upload_directory_steps`. Одного разрешения в `.env` для такого импорта недостаточно.

После подтверждённой отправки сценарий переносит выбранный XML из `root_dir` в `loaded_dir`. Если оригиналы нужно сохранить, используйте рабочие копии в `root_dir`.

## 2. certificate_selection_required и кэширование ЭЦП

Это требование явно подтвердить выбор ЭЦП, а не настройка кэширования.

- `false`: автоматический вход без списка сертификатов разрешён; организация затем всё равно сверяется по ИНН.
- `true`: если вход произошёл без явного выбора сертификата, сценарий остановится с `CERTIFICATE_NOT_VERIFIED`.

Если список сертификатов появился, сценарий выбирает подходящую ЭЦП по `certificate_inn`, а при его отсутствии — по `inn`, независимо от этого флага.

Сам параметр не очищает кэш и не заставляет СБИС показать список ЭЦП.

## 3. Два способа указать ведомства

Через массив:

```json
{
  "authority_prefixes": [
    {"authority": "FNS", "prefixes": ["NO_BOUPR", "NO_NDFL3"]},
    {"authority": "SFR", "prefixes": ["POVD"]}
  ]
}
```

Или для одного ведомства:

```json
{
  "authority_prefixes": null,
  "authority": "FNS",
  "prefixes": ["NO_BOUPR", "NO_NDFL3"]
}
```

Во втором варианте обязательно передать `authority_prefixes: null`: иначе массив из шаблона имеет приоритет. В массиве один орган указывается одним объектом; его префиксы объединяются в `prefixes`.

`ui` — технические настройки экранов СБИС: селекторы, кнопки, шаги и проверки. Для уже проверенных экранов РСВ ФНС и ЕФС-1 СФР можно не передавать `ui`.

Это два способа выбора ведомств. Режимы выполнения отдельно задаются через `mode`: `preflight`, `validate_only`, `send`. Для отправки также требуется `submit_enabled: true`.

## 4. Смысл allow_multiple

Параметр разрешает выбрать несколько самостоятельных отчётов одного ведомства.

В JSON 3.2.0 для каждого префикса выбираются все соответствующие XML. Отсутствующие префиксы пропускаются; полностью пустая выборка завершает задание успешно без Rezult_N и файлов артефактов. Например, два префикса ФНС могут выбрать два разных отчёта:

- `false` — остановиться, если для ведомства выбрано больше одного файла;
- `true` — разрешить несколько файлов.

Но текущий стандартный профиль отправки рассчитан на один XML каждого ведомства. Для отправки нескольких самостоятельных отчётов одного ведомства нужны дополнительные шаги точного повторного открытия карточек — `ui.reopen_steps`.

## 5. Один отчёт из трёх файлов

Пока не поддерживается. Сценарий не объединяет связанные XML в комплект и не определяет автоматически, что три файла принадлежат одному отчёту.

`allow_multiple: true` эту задачу не решает. Поддержку комплектов нужно отдельно реализовать и проверить на соответствующих файлах.

## 6. Значения ui по умолчанию

Полный JSON уже содержит общий `ui`. Для проверенных экранов его можно оставить без изменений.

- `context.ui` — общие настройки.
- `authority_prefixes[].ui` — переопределения для конкретного ведомства.

Для других видов отчётов или изменившегося интерфейса СБИС настройки могут потребовать корректировки. Настоящий отчёт Росстата пока не проверен.

Не передавайте `context.ui: {}`, если хотите сохранить настройки шаблона: переданный объект заменит общий `ui`.

Слияние настроек ведомства с общим профилем поверхностное: `{...context.ui, ...plan.ui}`. При совпадении поля побеждает настройка ведомства; вложенный объект или массив заменяется целиком.

## 7. Результат для каждого отчёта

После доработки 14.10.2026 каждому выбранному самостоятельному XML соответствует отдельный `job.result.Rezult_1`, `Rezult_2` и далее. Внутри этих структур нет коллекций или вложенных объектов: только строки, числа, Boolean и null.

В каждой структуре есть `state`, `report_state`, `inn`, `authority`, `section_name`, `mode`, `file_name`, `sha256`, `load_datetime`, `validation_result`, `validation_protocol`, `sbis_status`, `archived_path`, флаги подтверждения, `error_code` и `error_message`. Финансовые поля также плоские: `license_requires_confirmation`, `license_amount`, `license_currency`, `license_continuation`.

`authority` — код ведомства. `section_name` — имя раздела ФНС/СФР/Росстат после подтверждённой загрузки; до неё null. При остановке до соответствующего этапа другие значения также могут быть null. Протокол проверки не является официальной квитанцией ведомства.

Нумерация соответствует порядку выбора файлов внутри задания и не меняется при ошибках. Уже отправленный отчет сохраняет `state=sent`, необработанный — `not_processed`; неопределённая отправка — `requires_reconciliation`. Ошибка до выбора файлов может не содержать Rezult_N: используйте job.error.

Сценарий сохраняет все плоские результаты в `result-N.json` — объекте с ключами Rezult_1, Rezult_2 и далее. Для скачивания используйте его api_url и заголовок X-API-Key. Системный массив artifacts остаётся рядом с Rezult_N, а не внутри них.

Это новый контракт сценария 3.0.0; сохранённые задания предыдущей версии не преобразуются.
