# План демонстрации этапа 3

## Что доказывает демонстрация

Система принимает обычный Chrome Recorder JSON, выполняет его в реальном Chromium
через очередь и показывает результат без добавления специального обработчика под
почту. Эталонный сценарий состоит из 18 шагов и самостоятельно:

1. открывает реальный Yahoo Mail;
2. вводит логин `seeergo@yahoo.com` и пароль из `.env`;
3. дожидается загрузки почтового ящика;
4. открывает форму нового письма;
5. заполняет получателя `10sydneyfc@gmail.com`, тему и текст;
6. отправляет реальное письмо;
7. проверяет уведомление об отправке;
8. сохраняет итоговый скриншот в результате задания.

## Подготовка за 5 минут до показа

```bash
cp .env.example .env
npm ci
npm test
npm run demo:reset
docker compose up --build -d
docker compose ps
```

Проверьте в `.env`:

```text
UN_ID=un-demo-01
WEB_LOGIN=admin
WEB_PASSWORD=change-this-password
API_KEY=dev-secret
DEMO_MAIL_LOGIN=demo.user
DEMO_MAIL_PASSWORD=demo-password
YAHOO_MAIL_LOGIN=seeergo@yahoo.com
YAHOO_MAIL_PASSWORD=<пароль-выделенного-демо-аккаунта>
YAHOO_MAIL_RECIPIENT=10sydneyfc@gmail.com
BROWSER_HEADLESS=false
BROWSER_STEP_DELAY_MS=350
BROWSER_HOLD_OPEN_MS=5000
NOVNC_ENABLED=true
```

При Docker-запуске живое окно Chromium доступно через noVNC. Подключение по SSH и
параметры безопасности описаны в [`novnc-demo.md`](novnc-demo.md). Если живой показ не
нужен, установите `NOVNC_ENABLED=false`, `BROWSER_HEADLESS=true` и используйте финальный
скриншот в интерфейсе.

Заранее откройте две вкладки:

- `http://localhost:33001/` — сценарии, редактор и прогресс;
- `http://localhost:33001/queue` — очередь конкретной УН. Живой Chromium встроен в главную страницу.

Перед публичным показом один раз проверьте вход Yahoo на этой машине. Yahoo может
запросить CAPTCHA или дополнительное подтверждение — сценарий не обходит эти проверки и
в таком случае остановится с диагностическим скриншотом.

## Основной маршрут на 15 минут

### 1. Постановка задачи — 1 минута

Покажите первый экран и сформулируйте отличие от этапа 2: раньше браузерные шаги были
имитацией, теперь исполняется Chromium. Очередь, идентификаторы, логи и единая модель
результата при этом не меняются.

### 2. Формат сценария — 2 минуты

Откройте карточку **«Yahoo отправляет письмо»** в редакторе. Покажите:

- `title`, `description` и стандартные `steps[].type` из Chrome Recorder;
- альтернативные CSS/ARIA-селекторы;
- шаблоны `{{mail_to}}`, `{{mail_subject}}`, `{{mail_body}}`;
- конечный `waitForElement`, который подтверждает бизнес-результат.

Ключевой тезис: для другого сайта аналитик записывает новый JSON и передаёт его тому же
API — разработчик фабрики не добавляет новые `action` или маршруты.

### 3. Реальное выполнение — 4 минуты

Нажмите **«Запустить»**. Пока выполняются 18 шагов:

- покажите переход задания `queued → running → success`;
- обратите внимание на типы `navigate`, `click`, `change`, `waitForElement`;
- откройте `/queue` и покажите занятый слот этой УН;
- объясните, что тайм-аут и отмена работают через общий контроллер задания.

### 4. Доказательство результата — 3 минуты

После `success`:

- откройте артефакт `browser-final.png` в блоке «Результат браузера»;
- покажите письмо и зелёное уведомление «Письмо отправлено»;
- покажите уведомление Yahoo об отправке и при необходимости входящее письмо в Gmail;
- в журнале покажите 18 пар событий запуска/завершения шагов;
- в результате покажите `job_id`, внешний `uid`, `un_id` и `runtime`.

### 5. Самостоятельное создание — 3 минуты

Нажмите **«Новый»** и покажите чистый шаблон Recorder. Затем верните готовый сценарий,
измените получателя, тему или текст в `context` и запустите снова. Это демонстрирует
повторное использование одного JSON с разными входными данными.

Покажите документ [`script-creation.md`](script-creation.md): в нём описан весь путь от
записи DevTools до API и чек-лист передачи сценария.

### 6. Резерв — 2 минуты

Если осталось время, запустите **«Поиск в Яндексе»**: Chromium вводит запрос и открывает
первый органический результат. На серверных IP Яндекс может показать CAPTCHA; это
внешнее ограничение сайта, которое демонстрация намеренно не обходит. Затем запустите
один диагностический сценарий этапа 2 и покажите общую очередь.

## Резервный запуск из терминала

Если браузерная вкладка со студией была закрыта, сценарий запускается командой:

```bash
npm run demo:browser
```

Для Docker Compose:

```bash
DEMO_API_URL=http://127.0.0.1:33001 npm run demo:browser
```

Команда печатает прогресс `0/18 … 18/18` и полный результат с путём к скриншоту.
Сценарий Яндекса запускается командой `npm run demo:yandex`.

## Критерии успешного показа

- выполнены все 18 шагов;
- статус задания — `success`;
- `result.runtime` равен `puppeteer-replay`;
- Yahoo показал уведомление об отправке письма на `10sydneyfc@gmail.com`;
- доступен PNG-артефакт;
- в результате присутствуют `job_id`, `uid` и `un_id`;
- второй запуск с изменёнными данными не требует изменения кода системы.
