# Демо этапа 2: JSON-steps Interpreter

Актуальный маршрут этапа 4 (1С, callback, Windows/Яндекс Браузер, ресурсы,
параллельность и файловая система) находится в
[`docs/stage-4-1c-integration.md`](../docs/stage-4-1c-integration.md). Для его
нагрузочной части используйте `npm run demo:stage4:parallel`.

Для отдельного наглядного показа реальной работы с файлом запустите карточку
«Скачать и открыть файл» на главной странице или выполните:

```bash
npm run demo:file
npm run demo:file:error
```

Первый сценарий загружает XML, JSON, CSV и TXT по HTTPS, сохраняет их в каталог
артефактов задания, читает XML с диска и открывает локальную копию в Chromium.
Второй загружает встроенный HTML-документ, выполняет тот же файловый цикл и затем
предсказуемо завершается `VALIDATION_ERROR`, сохраняя частичный результат и debug-логи.
Для callback при запуске через runner задайте `DEMO_CALLBACK_URL`.

## Цель

За 12 минут доказать четыре свойства системы:

1. API принимает сценарий как данные и передаёт его локальной очереди.
2. Интерпретатор последовательно вызывает обработчики из step registry.
3. Результат шага попадает в контекст и используется следующими шагами через `{{variable}}`.
4. Логи, retry, тайм-ауты и ошибки имеют стабильный машинно-читаемый формат.

Реальная автоматизация браузера и СБИС не входит в этап 2. Шаги `launch_browser`,
`navigate`, `auth_ecp`, `upload_files`, `validate_report` и `submit_if_valid`
используют тестовые обработчики. Шаги `find_files` и `move_files` работают с реальными
файлами в `demo-data`.

## Подготовка

За 5 минут до встречи:

```bash
cp .env.example .env
# Указать UN_ID, WEB_LOGIN и WEB_PASSWORD
npm test
npm run demo:reset
npm start
```

Проверить:

- `http://localhost:3000/health` возвращает `status: ok`;
- `http://localhost:3000/` показывает четыре готовых демо-сценария;
- `http://localhost:3000/queue` показывает «API подключён»;
- `http://localhost:3000/docs` открывает русскоязычный Swagger UI;
- в `demo-data/incoming` находятся файлы `FNS_2026_Q2.xml` и `SFR_2026_Q2.xml`;
- в `demo-data/loaded` нет файлов.

Войти с данными из `.env`. Открыть `/` как основной экран, а `/queue` и `/docs` —
в соседних вкладках как дополнительные материалы. На главной ключ `dev-secret`
уже подставлен.

## Сценарий выступления

### 0:00–1:00 — границы этапа и маршрут

Сказать:

> На этом этапе мы показываем движок исполнения. Сейчас браузерные шаги подключены
> через mock-обработчики. На следующем этапе они будут заменены реализацией СБИС без
> изменения формата сценария, очереди, логов и модели ошибок.

На главной показать четыре карточки маршрута и редактор. Объяснить, что кнопка
«В редактор» позволяет разобрать JSON до запуска, а «Запустить» сразу отправляет
готовый пример в очередь.

### 1:00–5:00 — успешная цепочка

На карточке «Отчёт отправлен» нажать «В редактор». Коротко показать `context`,
шаблоны `{{found_files}}` и десять последовательных шагов, затем нажать
«Запустить» под редактором.

Обратить внимание:

- карточка попадает в «В очереди», затем в «Выполняются»;
- прогресс показывает номер и название текущего шага;
- после завершения карточка перемещается в «Завершены»;
- приоритет `P10` отображается на карточке.

На главной показать ход выполнения и журнал. Особо выделить:

- `find_files` нашёл два отчёта;
- `found_files` был подставлен в `upload_files` и `move_files`;
- выполнены все десять шагов;
- скачанная квитанция представлена в `result.artifacts`;
- файлы появились в `demo-data/loaded`.

Резервная команда:

```bash
npm run demo:success
```

### 5:00–7:00 — нормализованная ошибка

На карточке «Файл не найден» нажать «Запустить». После выполнения показать
четыре успешно завершённых подготовительных шага, остановившийся поиск файлов и
оставшиеся в ожидании загрузку, проверку, отправку, скачивание квитанции и
архивирование.

Показать поля:

```json
{
  "code": "FILE_NOT_FOUND",
  "retryable": false,
  "step_index": 1,
  "action": "find_files"
}
```

Подчеркнуть, что последующие шаги не запускаются, а 1С сможет обрабатывать ошибку
по `code`, не разбирая текст сообщения.

Резервная команда:

```bash
npm run demo:error
```

### 7:00–10:00 — retry

Запустить карточку «Повтор после сбоя». Первая попытка `auth_ecp` вернёт
`PLUGIN_NOT_RUNNING`, после
чего карточка пройдёт состояния:

```text
running → retrying → queued → running → success
```

В деталях показать две попытки и запись о задержке `backoff_ms`.

Резервная команда:

```bash
npm run demo:retry
```

### 10:00–12:00 — тайм-аут и итог

Запустить карточку «Контроль тайм-аута». После подготовки файлов и открытия портала
авторизация по ЭЦП задерживается на 1400 мс при тайм-ауте 300 мс и завершается с
`TIMEOUT_ERROR`. Следующие бизнес-шаги остаются на экране в ожидании.

```bash
npm run demo:timeout
```

Закончить тремя тезисами:

- последовательность автоматизации уже управляется JSON-сценарием;
- каждый шаг изолирован и может быть заменён реальной реализацией;
- очередь, контекст, логи и ошибки готовы для последующей интеграции с 1С.

## Полный автоматический прогон

При проблемах со Swagger или браузером:

```bash
npm run demo:all
```

Команда сама восстанавливает фикстуры перед каждым сценарием, создаёт задания,
показывает смену статусов и проверяет ожидаемый итог.

## Docker Compose

```bash
npm run demo:reset
docker compose up --build
```

Открыть:

- очередь: `http://localhost:33001/queue`;
- Swagger: `http://localhost:33002`.

Запуск резервного сценария:

```bash
DEMO_API_URL=http://127.0.0.1:33001 npm run demo:success
```

## Быстрое восстановление

- Старое задание вернулось вместо нового — изменить `Idempotency-Key`.
- Успешный сценарий не нашёл файлы — выполнить `npm run demo:reset`.
- Интерфейс показывает «Нет подключения» — проверить API-ключ и `/health`.
- Порт занят — задать другой `PORT` и тот же адрес в `DEMO_API_URL`.
- Для чистой истории использовать отдельный `DATA_DIR` перед запуском сервера.
