# Универсальные сценарии из JSON

С версии 0.6.14 формат `json-workflow` исполняет сценарий целиком из JSON. Исполнитель не знает, что такое СБИС, ведомство, ИНН, отчёт, сертификат или разрешение отправки. Все адреса, селекторы, проверки, циклы и условия задаются в файле сценария. Новый сайт не требует добавления обработчика в сервер.

Это расширение универсальной системы, а не стандартный экспорт Chrome Recorder: Recorder не описывает циклы, условия и файловые операции. Его обычные браузерные шаги используются внутри `browser_steps`. Нативный формат `puppeteer-replay` продолжает работать.

```json
{
  "format": "json-workflow",
  "context": { "numbers": [2, 5, 8] },
  "routines": {
    "add": [
      { "action": "compute", "params": { "expression": "context.sum + context.amount" }, "save_as": "sum" }
    ]
  },
  "steps": [
    { "action": "set", "params": { "sum": 0 } },
    {
      "action": "for_each",
      "params": { "items": "{{numbers}}" },
      "as": "number",
      "steps": [
        { "action": "call", "routine": "add", "params": { "amount": "{{number}}" } }
      ]
    },
    { "action": "compute", "params": { "expression": "({sum:context.sum})" }, "save_as": "answer" }
  ],
  "output": { "Rezult_1": "{{answer}}" }
}
```

Результат: `Rezult_1.sum = 15`. Этот сценарий не использует браузер или какой-либо конкретный сайт.

## Операции

| action | params / поля шага | Поведение |
| --- | --- | --- |
| `set` | объект переменных | Присвоить переменные верхнего уровня context. |
| `compute` | `expression`; `save_as` | Вычислить синхронное JavaScript-выражение над копией `context`. Доступа к Node, env и файловой системе нет; время вычисления ограничено 1 секундой. |
| `assert` | `condition`, `error_code`, `message` | Продолжить только при `condition === true`. |
| `fail` | `error_code`, `message` | Завершить сценарий с указанной ошибкой. |
| `if` | `condition`; поля `then`, `else` | Выполнить ветку `then` только при true, иначе `else`. |
| `for_each` | `items`; поля `as`, `index_as`, `steps` | Последовательно исполнить вложенные шаги для каждого элемента массива. |
| `call` | параметры вызова; поле `routine` | Исполнить массив шагов из `routines`. Параметры доступны через context внутри вызова. |
| `wait` | `duration_ms` | Пауза с поддержкой отмены. |
| `system_ip_check` | — | Системная проверка IP по настройкам УН. |
| `files_list` | `directory`; `save_as` | Перечислить файлы с именем, путём, размером, временем изменения и SHA-256. Фильтрация и выбор нужных файлов описываются в JSON. |
| `file_verify` | `file: {path, sha256}` | Проверить, что выбранный файл не изменён. |
| `file_archive` | `file: {path, sha256}`, `directory`; `save_as` | Проверить SHA-256, скопировать без перезаписи, проверить копию и источник, затем удалить источник. Условия разрешения операции задаёт JSON. |
| `file_copy` | `source`, `destination`; `save_as` | Скопировать файл без перезаписи. |
| `artifact_write` | `filename`, `text`, `mime_type`; `save_as` | Создать API-артефакт в каталоге задания. |
| `browser_launch` | `init_scripts` | Запустить одну сессию настроенного на УН браузера. |
| `browser_steps` | `steps`, `timeout_ms` | Исполнить стандартные шаги Recorder / Puppeteer Replay в текущей сессии. `customStep/uploadFiles` поддерживает input[type=file] и разрешённые пути. |
| `browser_eval` | `expression`; `save_as` | Вычислить выражение в браузере с доступом к DOM и `context`; допускается Promise. |
| `browser_wait` | `expression`, `timeout_ms`, необязательные `error_code`, `message`; `save_as` | Ожидать истинный результат выражения в браузере; сохранить полученное значение. |
| `browser_screenshot` | `filename` | Создать диагностический PNG-артефакт. |

`save_as` сохраняет результат операции в переменную. `title` и `description` показываются в истории выполнения. `private: true` скрывает параметры и результат шага в журнале. `output` определяет возвращаемые поля, например `Rezult_1`; внутренние переменные сценария остаются на УН. Артефакты добавляются к результату автоматически.

`{{variable}}` сохраняет тип значения, а `prefix {{variable}}` подставляет строку. Конфигурационные массивы браузерных шагов сохраняют шаблоны до исполнения `browser_steps`, поэтому имя текущего файла подставляется внутри каждой итерации. В JavaScript-выражениях предпочтительно читать `context.variable`, а не вставлять значение в исходный код строки.

Переменная элемента и индекс `for_each`, а также параметры `call` имеют область действия своего блока и затем восстанавливаются. Другие переменные, записанные через `set`, `compute` или `save_as`, сохраняются. Циклы последовательны; одновременно открыта одна браузерная сессия.

Для обычных операций действует `default_step_timeout_ms`, переопределяемый полем `timeout_ms` шага (число или шаблон переменной). У блоков `call`, `if`, `for_each` отдельного тайм-аута по умолчанию нет: действует тайм-аут задания и вложенных операций. При необходимости задайте блоку собственный `timeout_ms`.

`on_error` — массив универсальных шагов для формирования частичного результата. Код исходной ошибки доступен в `context.error.code`. При отмене задания этот блок не запускается, последующие действия прекращаются, браузер закрывается. При ошибке браузерного задания сохраняется диагностический снимок, если браузер доступен. Автоматическое повторение всего workflow после ошибки отключено через `retryable=false`; новый запуск требуется явно.

Файловые операции ограничены `FILESYSTEM_ALLOWED_ROOTS`, включая проверку реальных путей и ссылок. Лимиты: до 1000 элементов одного цикла, 10000 исполненных шагов, 25 уровней вложенности.

История содержит фактически выполненные вложенные шаги, включая итерации и вызовы. `total_steps` растёт по мере раскрытия веток; окончательное число известно после завершения. История сохраняется после перезапуска worker.

## API

В `POST /api/v2/jobs` передаётся либо `script` как объект, либо `script_text` как строка, содержащая весь JSON. Одновременно передавать оба поля нельзя. Параметры задания в `context` переопределяют значения `script.context`.

`GET /api/v2/interpreter/actions` возвращает универсальные операции в `formats.json-workflow`. Старый `json-steps` сохраняется для совместимости с демонстрациями; его имитационные действия не используются новым workflow.

Формат `sbis-report` удалён из исполнительного пути. Старые JSON этого формата необходимо заменить новым `demo/sbis-report-full.json`; автоматической скрытой конвертации нет.
