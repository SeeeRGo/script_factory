# Полный процесс СБИС

`sbis-report-full.json` содержит все 12 этапов раздела 4.2 «Системный анализ_v3.pdf» и исполняется worker начиная с 0.6.9 в формате `sbis-report`. `sbis-report-full.request.json` — тело POST `/api/v2/jobs`; перед запуском заполните параметры в `context`. Это отдельный исполнитель реальных браузерных и файловых действий, а не старые демонстрационные обработчики с похожими именами.

## Несколько ведомств в одном задании (worker 0.6.11+)

Обновлённый шаблон рассчитан на ФНС, СФР и Росстат. Передайте соответствия ведомств и префиксов в `context` запроса (или `parameters.context` при использовании обёртки API):

```json
{
  "authority_prefixes": [
    { "authority": "FNS", "prefixes": ["NO_"] },
    { "authority": "SFR", "prefixes": ["SFR_"] },
    { "authority": "ROSSTAT", "prefixes": ["STAT_"] }
  ]
}
```

Префиксы приведены как пример: замените их на префиксы ваших файлов. `sbis-report-full.request.json` содержит готовую структуру запроса с заполнителями. Сам `sbis-report-full.json` передаётся объектом в `script` или целиком сериализуется в строку `script_text`.

Порядок соответствует массиву. Проверка IP, запуск браузера и вход по ЭЦП выполняются один раз. Затем для каждого ведомства последовательно выполняются шесть этапов: выбор ведомства/организации → поиск → загрузка с проверкой → оценка протоколов → условная отправка → архивирование. API показывает 24 шага для трёх ведомств (12 для одного, 18 для двух). Исходные 12 этапов JSON являются шаблоном, повторять их вручную не требуется.

Допускаются от одного до трёх разных ведомств. Для прежнего одиночного режима задайте `authority_prefixes: null`, `authority` и `prefixes`. Без `authority_prefixes` старые сценарии также продолжают работать. Массив целиком заменяет одиночные параметры.

До первой загрузки проверяются файлы всех ведомств. Отсутствующий XML вызывает `FILE_NOT_FOUND`, назначение одного файла двум ведомствам — `AUTHORITY_FILE_CONFLICT`; загрузка не начинается. Для разных интерфейсов можно задать `ui` внутри элемента массива: его поля заменяют соответствующие поля общего `context.ui`. Обязательные привязки всех ведомств проверяются до запуска браузера в рабочих режимах.

При ошибках проверки отчёта отправка файлов этого ведомства пропускается, обработка следующего продолжается. При технической ошибке процесс останавливается; результаты уже обработанных ведомств сохраняются, непройденные остаются `pending`. Подтверждённые отправки не откатываются, повтор всего задания автоматически не выполняется. Если ошибка случилась после начала отправок, общее состояние консервативно становится `requires_reconciliation`: перед повторным запуском необходимо проверить результаты по файлам.

**Ограничение текущего шаблона:** фактические пути отчётов СФР/Росстата и привязки настоящих карточек ещё требуют проверки в СБИС. В `preflight` используется переход по пунктам меню, непроверенный путь отмечается `reports_section_verified=false`. Режимы `validate_only`/`send` не запустятся с незаполненными обязательными привязками. Поддержка цикла по трём ведомствам сама по себе не устраняет это ограничение.

## Режимы

- `preflight`: реальная проверка внешнего IP, запуск браузера, вход по ЭЦП, переход в отчётность, открытие ведомства, проверка ИНН при наличии UI-привязки, поиск файлов. Этапы обработки и отправки отчётов явно пропускаются. `success` задания означает окончание диагностики; смотрите `Rezult_1.phases`, где есть `verified`, `partial`, `skipped`.
- `validate_only` (по умолчанию): выбирает XML, подтверждает карточку по имени файла и ИНН, нажимает «Проверить», сохраняет текст протокола. Отправка и архивирование не выполняются.
- `send`: дополнительно требует `submit_enabled: true`. После успешной проверки всех файлов повторно открывает и проверяет каждую карточку, выполняет настроенные действия отправки, ждёт точный статус «Отправлен» и только затем архивирует исходники и протоколы.

## Подготовка УН и параметры

Worker и установленное приложение Saby должны работать в интерактивном сеансе одного пользователя. Должны быть доступны его ЭЦП и CryptoPro. Начиная с worker 0.6.12 вход поддерживает диалог выбора нескольких подписей: выбор по ИНН выполняется отдельным обработчиком, после клика «По ключу подписи». Запись ввода PIN, если он требуется, задаётся в `ui.certificate_after_steps`.

Обязательные параметры: `inn`, `authority_prefixes`, `root_dir`, `loaded_dir`. Каталоги должны существовать и быть разрешены в `FILESYSTEM_ALLOWED_ROOTS`. Для каждого префикса выбирается один последний XML по времени изменения; совпавшие пути объединяются. Поиск выполняется непосредственно в `root_dir`, без рекурсии. `allow_multiple: false` запрещает несколько файлов в пределах одного ведомства.

Внешний IP проверяется существующей системной функцией: ipify сравнивается с `ip_adress` из настроек IP-монитора УН. Путь задаётся серверной переменной `IP_MONITOR_SETTINGS_PATH`. Подмена IP значением из JSON не поддерживается.

Готовая последовательность `ui.upload_steps` открывает папку «Загрузки» в файловом диалоге Saby. Для её использования **root_dir должен указывать на эту же папку пользователя worker**, а не на произвольный каталог. Если отчёты находятся в другом каталоге, запишите навигацию к нему в `upload_steps`. Сценарий не копирует отчёты в «Загрузки» автоматически. `{{file_name}}` и `{{file_path}}` подставляются для каждого найденного файла.

## Выбор ЭЦП по ИНН (worker 0.6.12+)

`inn` задаёт организацию для отчётов. `certificate_inn` задаёт ИНН в строке подписи; при `null` используется `inn`. Это позволяет отдельно задать ИНН владельца сертификата, если он отличается от ИНН организации.

```json
{
  "inn": "REPLACE_WITH_ORGANIZATION_INN",
  "certificate_inn": "REPLACE_WITH_CERTIFICATE_INN",
  "certificate_selection_required": true
}
```

После открытия способа «По ключу подписи» исполнитель ждёт список или завершение автоматического входа. Если список появился, он выбирает ровно одну видимую пригодную подпись с полным совпадением ИНН; совпадение десяти цифр с частью двенадцатизначного ИНН исключено. Подписи из группы Saby «нельзя воспользоваться» исключаются даже при её раскрытии, также исключаются скрытые/отключённые строки. Исполнитель использует оценку пригодности Saby, самостоятельно криптографическую цепочку сертификата не проверяет.

Проверенные селекторы новой УН:

- `ui.certificate_rows_selector`: `.auth-CertChooserStep .controls-ListView__itemV`;
- `ui.certificate_unusable_selector`: `.controls-SpoilerView, [aria-disabled="true"], [disabled]`;
- `ui.certificate_after_steps`: дополнительные Replay-шаги после выбора, если окружению нужны дополнительные подтверждения.

Нулевая численность совпадений даёт `CERTIFICATE_NOT_FOUND`, несколько пригодных подписей с одним ИНН — `CERTIFICATE_AMBIGUOUS`. Первый элемент произвольно не выбирается. Отсутствующая подпись не вызывает вход другой подписью. При `certificate_selection_required=true` автоматический вход без явного выбора даёт `CERTIFICATE_NOT_VERIFIED`. По умолчанию `false` сохраняет поддержку прежней УН с единственной автоматически выбранной ЭЦП; в результате такой вход имеет `certificate_selected=false`.

`skip_security_setup=true` (по умолчанию) нажимает «Пропустить» на необязательном экране «Настройка безопасности», не создавая логин и пароль. При `false` возвращается `AUTH_SECURITY_SETUP_REQUIRED`. Экран первичной регистрации ИП/организации автоматически не заполняется: возвращается `AUTH_ACCOUNT_SETUP_REQUIRED`. В таком случае этап `auth_ecp` имеет `partial`, `authenticated=false`, но сохраняет `certificate_selected=true` и ИНН уже выбранной подписи.

Результат этапа `auth_ecp` содержит `authenticated`, `certificate_selected`, а при явном выборе — `certificate_inn` и `eligible_certificate_count`. Выбор подписи подтверждает способ входа; выбранная организация в разделе отчётности дополнительно проверяется своим этапом по `inn`.

## UI-привязки и оставшиеся этапы настоящего отчёта

Значения `null` и пустые массивы в `context.ui` намеренно обозначают отсутствующие привязки, а не готовые селекторы. Заглушка открывает просмотр XML и не позволяет узнать интерфейс карточки отчётности. Пока обязательные привязки отсутствуют, `validate_only`/`send` завершатся с `UI_BINDING_REQUIRED` до запуска браузера.

| Поле | Что требуется |
|---|---|
| `authority_steps` / `authority_paths` | Переход на вкладку «Отчеты» и ожидаемый путь. Проверены ФНС `/page/fns`, СФР `/page/sfr`, Росстат `/page/stat` |
| `organization_steps` | Проверенные шаги открытия организации через профиль текущего пользователя. Для выбора другой организации в многопользовательском кабинете требуется своя запись |
| `organization_selector` | Проверенное поле `.ourCompanies-Requisites__INNField` в реквизитах организации |
| `organization_after_steps` | Необязательные действия после чтения реквизитов; в шаблоне пусто. После проверки исполнитель возвращается по `authority_paths` в отчёты текущего ведомства и повторяет `authority_steps` |
| `report_scope_selector` | Проверенная область НДС `.report-theme__contrastWrapper`; требуется ровно одна видимая карточка и полный ИНН |
| `upload_steps` | Запись выбора файла из правильного каталога и открытия карточки отчёта |
| `validate_steps` | Проверенная кнопка «Проверить» внутри `.controls-Popup__lastItem`; верхняя панель кнопок находится вне блока реквизитов `.report-theme__contrastWrapper`; запуск подтверждён на тестовой копии НДС |
| `validation_status_selector` | CSS-селектор результата относительно карточки |
| `validation_success_text` / `validation_failure_text` | Точные конечные тексты успешной/неуспешной проверки |
| `protocol_selector` | CSS-селектор текста протокола относительно карточки |
| `reopen_steps` | Повторное открытие именно данного отчёта перед отправкой |
| `submit_steps` | Полная запись отправки, включая необходимые подтверждения; сейчас первая кнопка «Отправить» подтверждена на черновике НДС; подтверждения подписи и отправки ещё требуются |
| `sent_status_selector` | CSS-селектор статуса относительно карточки, ожидается точный текст «Отправлен» |

Импорт и индивидуальная проверка выполняются вместе в этапе `upload_files`, чтобы не потерять открытую карточку при переходе к следующему файлу. Этап `validate_report` проверяет общие результаты. Перед отправкой проводится повторная проверка текущей карточки. Если СБИС не завершил проверку или не показал ожидаемый статус, ожидание завершается ошибкой; отсутствие ошибки в интерфейсе не считается успешной проверкой.

## Файлы, ошибки и результат для 1С

После поиска сохраняется SHA-256 исходника; изменение файла до загрузки/архивирования прекращает обработку. Архивирование не перезаписывает существующие файлы. Текст протокола копируется в архив, а его API-артефакт сохраняется. Исходный XML переносится только после подтверждённой отправки всех файлов текущего ведомства. Для защиты от повторной отправки автоматические повторы задания отключены; при неопределённом результате отправки требуется сверка с СБИС, а не повторный запуск.

`Rezult_1` содержит `state`, `inn`, `authority`, `authorities`, `mode`, `reports`, `phases`. При нескольких ведомствах верхнее `authority=null`; в `authorities` перечислены состояния каждого ведомства, в файлах и ведомственных этапах указано `authority`. В `reports` возвращаются имя файла, SHA-256, дата загрузки, результат проверки, ссылка на протокол, статус СБИС и путь архива. Внешний IP не раскрывается; возвращается результат его сверки. Существующая доставка callback системы передаёт тот же результат в 1С, если настроена в запросе и на УН. Доставка в реальную 1С в этой отладке не проверялась.

Состояния результата: `preflight_completed`, `validated_not_sent`, `validation_failed`, `sent`, `failed`, `requires_reconciliation`. `success` задания в режиме диагностики/проверки не означает отправку. Ошибки проверки СБИС дают статус задания `validation_failed` и сохраняют доступные протоколы. При ошибке после начала отправки возвращается `requires_reconciliation`; исходники автоматически повторно не отправляются.

## Дополнительная проверка реального НДС на новой УН (0.6.13)

С разрешения владельца существующий сданный НДС выгружен только на УН. XML в локальный проект не скачивались. Исходные файлы проверены по SHA-256 и не изменены. Для отладки на УН создана отдельная копия комплекта: новый идентификатор, IV квартал 2026 года, корректировка 99. Отправка отключена.

Основная часть импортирована в отдельный несданный черновик. Нажатие «Проверить» открыло панель «Найденные ошибки» (пять ошибок, в том числе отсутствие разделов 8 и 9). Это подтверждает импорт и запуск проверки, но не успешную проверку полного комплекта. Повторный импорт того же XML СБИС отклоняет как уже загруженный.

Файловый диалог показывает распознанное название отчёта вместо имени XML. Шаблон выбирает строку по точному `data-minicard-name`; исполнитель также проверяет полный `data-minicard-path` и единственность видимой строки. Несовпадение завершает задание с `FILE_SELECTION_MISMATCH` до двойного клика. `root_dir` должен соответствовать фактически открытому каталогу, при вложенном каталоге нужно дополнить `upload_steps` переходом в него.

В реальной карточке НДС имя исходного XML отсутствует и в тексте, и в DOM-атрибутах. Исполнитель 0.6.13 поддерживает `report_identity_mode=selected_file_and_key`: до импорта карточка должна быть закрыта, XML подтверждается по исходному имени и полному пути, после импорта сверяется полный ИНН и фиксируется ключ новой карточки. При последующих проверках ключ должен совпадать. Повторное открытие тестовой карточки подтвердило сохранение ключа. Внутренний ключ не возвращается в JSON; поля `file_selection_verified` и `report_key_verified` содержат только признаки подтверждения. Получение ключа через `report_key_expression` использует внутреннюю структуру Saby, поэтому изменение интерфейса может остановить выполнение. Старые записи без этого режима сохраняют сверку имени XML в карточке. Загрузка связанных разделов НДС одним комплектом ещё требуется. Для ФНС в `authority_prefixes[0].ui` записана отдельная панель ошибок: `validation_scope_selector`, `validation_status_selector`, `protocol_selector`, `validation_failure_text`. Она позволяет сохранить текст видимой панели ошибок, но не является подтверждённой привязкой успешной проверки или полного выгружаемого протокола СБИС. Привязки СФР/Росстата и подтверждённой отправки остаются незаполненными. Кнопка нового черновика называется «Отправить», дальнейшие подтверждения не проверялись. Реальные отчёты не отправлялись.


Повторный импорт распознаётся по `upload_duplicate_text` и завершается с `REPORT_ALREADY_IMPORTED`, без автоматического повтора и отправки. Открытая до начала импорта карточка, отсутствующее подтверждение файла, неоднозначная область карточки и несовпадение её ключа возвращают `REPORT_IDENTITY_MISMATCH`. Отсутствие обязательных привязок протокола и итогового статуса сохраняет `UI_BINDING_REQUIRED` до запуска браузера.


`report_identity_steps` раскрывает «Развернуть», если реквизиты новой карточки ещё свёрнуты. Исполнитель ждёт полного ИНН после раскрытия; раннее появление контейнера не считается готовностью реквизитов. Это исправляет остановку `REPORT_IDENTITY_MISMATCH` после импорта нового черновика со скрытым ИНН.

Точный путь в диалоге подтверждён на УН: `job_cbccbd5e-c113-43ac-8150-10da6463371f`, `filename_unique=true`, `full_path_exact=true`. Сохранение ключа при повторном открытии и различие ключей тестового/сданного отчётов подтверждены `job_40f57f98-0873-4b77-a5d9-7a1a032f93d8`; значения ключей в проект не выгружались. Локально прошли **127/127** теста проекта.

При нескольких самостоятельных XML одного ведомства исполнитель после проверки файла сверяет ключ предыдущей карточки и возвращается на страницу ведомства перед следующим импортом. Проверка «до импорта нет открытой карточки» сохраняется. Это обработка отдельных отчётов, а не связанных разделов одного НДС.

Полный исполнитель использует большой viewport в headless и `defaultViewport=null` в оконном режиме, как основной Puppeteer Replay. Это исключает стандартную эмуляцию 800×600, не соответствующую записанному интерфейсу Saby. Фактические `viewport_width` и `viewport_height` возвращаются в фазе `launch_browser`.

Кнопка проверки: `validate_steps` ожидает единственную видимую и доступную кнопку «Проверить» в окне карточки, прокручивает надпись в область видимости и проверяет её через `elementFromPoint` и затем выполняет одно нажатие мышью. Локально проверено перекрытие кнопки временным слоем; привязка подтверждена отдельным Recorder-запуском и полным API-сценарием на УН. При запуске используется первая вкладка браузера, как в Recorder Replay.

Проверка на Windows/Yandex: **43/43** теста модулей `sbis-workflow` и `sbis-identity` прошли. Отдельная проверка синтетического нулевого НДС также открыла «Найденные ошибки» (`job_77fb03c9-0ee0-4a4b-9d9a-9e56ea2b09a3`); успешный результат проверки корректного комплекта этим не подтверждён. Полный API-запуск `job_444fdca5-df9b-4938-88cb-156e30cd4d6c` подтвердил исходный файл и ключ карточки, но остановился на ожидании доступности кнопки до сохранения протокола. Отправки и перемещения файлов не было.

Итоговый запуск полного исполнителя на новой тестовой копии: `job_53762444-b254-46c7-a1f1-82a464182917`, **12/12 шагов**, `validation_failed` / `VALIDATION_ERROR`. Подтверждены исходный файл, полный ИНН и ключ карточки; текст панели проверки сохранён в артефакт на УН (`protocol_saved=true`). `sent=false`, `archived=false`. Это ожидаемый результат для неполной тестовой декларации с ошибками, а не сбой UI. Новая прокрутка и физическое нажатие отдельно подтверждены `job_10137972-b872-4671-b125-4cec43bdc97c` (**20/20 шагов**).

Остаются непроверенными положительный протокол корректного комплекта, совместная загрузка связанных разделов НДС, импорт/проверка настоящих XML СФР и Росстата, а также подписание/отправка и её итоговый статус. Для второго сертификата по-прежнему требуется ручная первичная регистрация кабинета; она не выполнялась.
