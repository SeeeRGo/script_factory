# План реализации проекта

## 1. Цель проекта

Реализовать распределенную систему исполнения скриптов автоматизации на удаленных УН.

1С хранит и версионирует JSON-скрипты, отправляет их на локальный API-сервис УН, сервис ставит задания в очередь, выполняет шаги автоматизации через браузер/СБИС, возвращает статус, результат, ошибки и логи.

## 4. Этап 0. Подготовка и уточнение контура

Оценка: 16-24 ч.

Задачи:

- Зафиксировать целевые ОС УН, доступы и способ запуска сервиса.
- Подтвердить наличие тестовой УН со СБИС, ЭЦП, СБИС Плагином и доступом к каталогам отчетов.
- Уточнить, будет ли 1С принимать callback или первый релиз работает через polling.
- Согласовать минимальный набор JSON-steps для первой версии.
- Зафиксировать формат логов, сроки хранения, API-key, HTTPS и сертификаты.

Результат:

- Технический backlog.
- Согласованный MVP-сценарий.
- Подготовленное тестовое окружение.

## 5. Этап 1. API-сервис и локальная очередь

Оценка: 80-96 ч.

Задачи:

- Создать Node.js/TypeScript API-сервис.
- Реализовать OpenAPI-контракт `/api/v2`.
- Реализовать методы:
  - `POST /jobs`
  - `GET /jobs`
  - `GET /jobs/{job_id}`
  - `POST /jobs/{job_id}/cancel`
  - `GET /jobs/{job_id}/logs`
  - `GET /health`
  - `GET /system/resources`
  - `GET/PUT /system/config`
- Реализовать локальную очередь FIFO с приоритетом.
- Возвращать в health-check идентификатор УН и локальное состояние очереди:
  число ожидающих и выполняющихся заданий, лимит параллельности и свободные слоты.
- Реализовать статусы `queued`, `running`, `retrying`, `success`, `failed`, `validation_failed`, `cancelled`, `timeout`.
- Реализовать `retry_policy`, таймауты и идемпотентность по `uid`.
- Добавить базовую авторизацию через `X-API-Key`.

Демо:

- Сервис принимает задания.
- Возвращает `job_id`.
- Показывает статус, очередь и health-check.
- Имитирует выполнение задания без реальной автоматизации.

## 6. Этап 2. JSON-steps Interpreter

Оценка: 80-96 ч.

Задачи:

- Реализовать движок исполнения JSON-steps.
- Описать контракт шага: `action`, `params`, timeout, обработка ошибок.
- Реализовать подстановку параметров: `{{root_dir}}`, `{{loaded_dir}}`, `{{found_files}}`, `{{prefixes}}`.
- Реализовать step registry.
- Реализовать базовые шаги:
  - `check_ip`
  - `launch_browser`
  - `navigate`
  - `auth_ecp`
  - `find_files`
  - `upload_files`
  - `download_files`
  - `validate_report`
  - `submit_if_valid`
  - `move_files`
- Реализовать нормализованную модель ошибок: `IP_MISMATCH`, `FILE_NOT_FOUND`,
  `AUTH_ERROR`, `UPLOAD_ERROR`, `DOWNLOAD_ERROR`, `VALIDATION_ERROR`,
  `TIMEOUT_ERROR`, `PLUGIN_NOT_RUNNING`.
- Добавить unit/integration тесты интерпретатора.
- Возвращать в `result` идентификаторы `job_id`, `uid`, `un_id` и файловые
  артефакты скачивания в согласованном формате `artifacts[]`.

Демо:

- В API передается JSON-скрипт.
- Сервис выполняет цепочку шагов.
- Логи показывают каждый шаг.
- Ошибки возвращаются в согласованном формате.

## 7. Этап 3. AutomationScript и реальная автоматизация СБИС

Оценка: 48-72 ч.

Задачи:

- Интегрировать Puppeteer/Chrome.
- Реализовать запуск браузера на УН.
- Настроить работу с окнами, диалогами и выбором ЭЦП.
- Реализовать поиск отчетов по префиксам и органам: `FNS`, `SFR`, `ROSSTAT`.
- Реализовать загрузку одного или нескольких файлов.
- Заменить mock-обработчик `download_files` реальным скачиванием и заполнять
  метаданные артефактов: путь, размер, MIME-тип и SHA-256.
- Реализовать проверку протокола валидации.
- Реализовать отправку отчета при успешной проверке.
- Реализовать перенос файлов в `Загружено`.
- Добавить диагностику нестабильных мест UI СБИС.

Демо:

- На тестовой УН запускается реальный сценарий.
- Отчет находится, загружается, проверяется и отправляется.
- При ошибке возвращается понятное сообщение для 1С.

Демо:

## 11. Рекомендуемые вехи

- M1: API + очередь + mock execution.
- M2: JSON-steps interpreter + логи + retry.
- M3: первый реальный сценарий СБИС на тестовой УН.
- M4: интеграция 1С через polling.
- M5: E2E-приемка.
- M6: пилотный деплой и документация.

## 12. Ключевые риски

- Нет тестовой УН на старте: блокирует реальную автоматизацию СБИС.
- Изменения UI СБИС: нужен изолированный слой шагов и быстрый выпуск фиксов.
- ЭЦП и СБИС Плагин: возможны нестабильные сценарии авторизации.
- Callback в 1С: не делать критичным для MVP.
- Параллельность на УН: для ЭЦП и Chrome безопаснее начать с `max_parallel_jobs = 1`.
- Массовый деплой: заранее проверить WinRM/SSH/права администратора.

## 13. MVP

Минимальная версия должна включать:

- API с очередью.
- Polling из 1С.
- JSON-steps interpreter.
- Реальный сценарий загрузки, валидации и отправки отчета в СБИС.
- Логи, доступные из 1С.
- Retry и понятные ошибки.
- Ручной или полуавтоматический деплой на пилотную группу.

Callback, массовый Ansible-деплой на все УН и расширенный мониторинг лучше делать после подтверждения MVP на тестовой УН.
